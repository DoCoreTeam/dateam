## 이 조사가 못 세는 것

- **「안 불린다」가 아니라 「안 적혀 있다」를 센다.** 서버 액션과 prop 으로 넘어간 주소를
  안 따라가면 멀쩡한 창구를 고장으로 센다 — 실측으로 114개가 그렇게 잡혔고,
  `useCrmBulk` 가 `endpoint` 를 prop 으로 받아 런타임에 주소를 만드는 것이 원인
- **자원마다 CRUD 가 다 있는지는 안 센다.** `POST /rollback` 처럼 자원이 아닌 동작 창구가
  많아, 자원을 가리는 모델 없이 세면 「만들기는 있고 지우기가 없는 자원 110개」 같은
  못 믿을 숫자가 나옴. F-3 의 그 부분은 별건으로 남김
- `lib/ci/crud-coverage.test.ts` 는 같은 일을 **`/api/ci` 안에서만** 더 정밀하게 함
  (주소와 메서드 짝까지 봄). 이 조사는 그보다 거칠고 **저장소 전체**를 봄

## 권한은 여기서 안 셈

처음에 열하나의 인증 여부를 세려다 **틀린 숫자를 얻었음** — 인증 도움 함수 목록을
손으로 들어 `requireCiMemberApi` 를 빠뜨려 「인증 없는 창구 7개」가 나왔고, 실제로는
그 자리가 전부 인증을 지남

창구 권한은 `apps/web/lib/policy/api-auth-surface.test.ts` 가 이미 **전수로** 봄
열어 둔 창구는 그 파일 `OPEN_ON_PURPOSE` 에 이유와 함께 적혀 있어야 하고 지금 초록임
그래서 이 조사에서 권한을 다시 세지 않음

## 링크가 빠진 자리는 기계가 안 셈

F-4 의 앞쪽 — 「목록 항목·연결된 객체·건수·알림·이력에서 상세로 갈 길이 있나」 — 는
기계가 세지 않음

왜: 「이 값에 상세가 있어야 하나」는 업무 판단임
없는 링크를 전부 만들라고 강요하면 F-4 가 같은 줄에서 금지한
「상세가 없는 값까지 누르게 만들기」가 되어 규칙이 자기와 부딪힘
