# 다중 세션 동시 작업 정책 (전문 · SSOT)

> **이 문서가 원본이다.** `CLAUDE.md` · `AGENTS.md` · `GEMINI.md`에는 **안 읽으면 사고 나는 규칙만** 압축 카드로 인라인되어 있고, 나머지(근거·표·예외)는 여기에 있다.
> 카드와 이 문서가 어긋나면 **이 문서가 맞다.** 규칙을 고칠 때는 여기를 고치고, 카드에 인라인된 항목만 3파일에 반영한다.

## 왜 이 정책이 있나

이 저장소는 Claude Code 창 여러 개 · Codex · Ralph 루프가 **동시에** 같은 것을 공유한다.

| 공유 자원 | 결과 |
|---|---|
| 작업 트리 (`main` 단일 worktree) | 인덱스가 하나 → **남의 staged 변경이 내 커밋에 실린다** |
| dev 서버 (:3000) | 내가 보는 화면에 **남의 중간 저장 상태**가 섞인다 |
| 운영 DB (Supabase) | 마이그레이션 동시 적용 = 되돌릴 수 없다 |
| 버전·마이그 번호 | 두 세션이 같은 번호를 쓴다 |
| `node_modules` · `.next` | 한 세션의 build/install이 남의 dev 서버를 깬다 |

세션은 서로를 볼 수 없다. 그래서 **규칙이 유일한 조정 수단**이다.

### 실측 — 기존 규칙으로는 막지 못한다

기존 정책은 "내가 바꾼 파일만 경로로 지정해 스테이징한다"였다. 실험으로 확인한 결과:

```
세션 A가 `git add a.txt`만 해 둠
  → 세션 B가 `git add b.txt && git commit`
  → 커밋에 a.txt가 함께 들어감          ❌
```

인덱스(staging area)는 **작업 트리마다 하나뿐**이라 세션끼리 공유되기 때문이다. 경로를 지정해 `add`해도, `commit`은 인덱스 **전체**를 커밋한다.

```
세션 A가 `git add a.txt`만 해 둠
  → 세션 B가 `git commit -m "..." -- b.txt`
  → 커밋에 b.txt만 들어가고, A의 a.txt는 인덱스에 그대로 남음   ✅
```

`git commit -- <경로>`는 인덱스를 **우회**해 지정 경로의 작업트리 내용만 커밋한다. — 이것이 M-1이 존재하는 이유다.

---

## M-1. 커밋은 pathspec 커밋으로만 한다

```bash
# ✅ 유일하게 허용되는 커밋 형태
git commit -m "v0.7.x: 내용 claude" -- apps/web/app/foo/page.tsx apps/web/lib/foo.ts

# ✅ 신규(untracked) 파일은 add가 선행되어야 한다. 커밋은 그래도 pathspec으로.
git add apps/web/lib/new.ts
git commit -m "v0.7.x: 내용 claude" -- apps/web/lib/new.ts

# ❌ 금지 — 인덱스 전체를 커밋한다
git add <경로> && git commit -m "..."
git add -A   /   git add .   /   git commit -a
```

- 커밋 직전 확인은 `git status --short -- <경로>` + `git diff HEAD -- <경로>`.
  **`git diff --cached`로 확인하지 말 것** — pathspec 커밋의 실제 내용(작업트리)과 다르다.
- 경로는 **디렉터리가 아니라 파일 단위**로 적는다. `apps/web/lib/`처럼 디렉터리를 지정하면 그 밑에 생긴 **남의 새 파일**을 삼킨다.
- ⚠️ **route group 경로는 반드시 따옴표로 감싼다.** zsh가 괄호를 glob으로 해석해 `no matches found`로 죽는다 — 이때 `git add -A`로 되돌아가는 것이 사고의 시작이다.
  ```bash
  git commit -m "..." -- "apps/web/app/(member)/weekly-report/page.tsx"
  ```
- 커밋 후 `git show --stat --name-only HEAD`로 **내가 적은 파일만** 들어갔는지 확인한다.
- 남의 파일이 섞였으면 **스스로 되돌리지 말고 사용자에게 보고**한다. 그 사이 다른 세션이 이미 내 커밋 위에 커밋했을 수 있어, `reset`·`amend`가 남의 커밋을 함께 날린다.

## M-2. 공유 트리 배타 명령 — 트리 전체를 건드리는 것은 금지

> 아래 명령들에는 "내 파일"이라는 개념이 없다. 작업 트리 **전체**에 작용하므로, 실행하는 순간 다른 세션의 미저장 작업이 사라지거나 되돌아간다.

| 명령 | 무슨 일이 벌어지나 | 규칙 |
|---|---|---|
| `git stash` · `stash pop` | 트리 전체를 치운다 — **남의 미커밋 변경이 통째로 사라진다** | **절대 금지** |
| `git checkout <브랜치>` · `switch` · `restore .` | 트리를 갈아끼운다 | **절대 금지** (브랜치 전환은 사용자만) |
| `git reset --hard` · `clean -fd` · `rebase` · `merge` | HEAD·트리 전역 변경 | **절대 금지** |
| `git push` | 원격 반영 | **금지** — 사용자가 직접 한다 |
| `pnpm build` (dev 서버 가동 중) | `.next` 캐시 충돌로 남의 dev 서버가 깨진다 | **금지** (기록된 사고) |
| `pnpm install` · lockfile 변경 | `node_modules` 전역 교체 | 단독 창구 + 보드 공지 |
| `scripts/migrate.sh` | **운영 DB 공유** — 되돌릴 수 없다 | 단독 + 공지 + 사용자 승인 |
| `pkill` · dev 서버 종료·재시작 | 남이 검증 중인 세션을 죽인다 | **금지** — 사용자에게 요청 |
| `eslint --fix` · formatter 일괄 실행 | 내 범위 밖 파일까지 고쳐 놓는다 | **내 파일 경로만** 인자로 |

근본 해결책은 **세션별 `git worktree` 분리**다. 현 운영은 공유 트리를 전제하므로, **대형 리팩터 · 파일 삭제 · 브랜치 작업**처럼 트리 전역을 흔드는 일은 worktree를 따로 파거나 사용자에게 단독 시간을 요청한다.

## M-3. 번호 선점 충돌 — 버전 · 마이그레이션 · changelog

### 버전 (낙관적 잠금)

`git log` 확인만으로는 동시 선점을 막지 못한다. 확인이 아니라 **선점 후 재확인**이 규칙이다.

1. 버전 번프는 **커밋 직전에만** 한다. 작업 도중 미리 올려 두지 않는다(그 시간만큼 충돌 창이 넓어진다).
2. `git log --oneline -10`에서 **최대 버전** 확인 → +1 → 5개 파일(package.json ×2 + 정책 3파일) 수정 → **곧바로** pathspec 커밋. 사이에 다른 작업을 끼우지 않는다.
3. 커밋 **직후** `git log --oneline -5` 재확인. 같은 버전이 둘이면 **나중에 커밋한 쪽이 양보**한다.
   - `HEAD`가 **아직 내 커밋이면** `git commit --amend`로 +1 재조정 (push 전이라 안전).
   - 그 사이 **다른 세션이 이미 그 위에 커밋했으면 amend·reset 금지.** 남의 커밋을 함께 날린다. 이때는 버전 5파일만 +1로 고쳐 **후속 커밋 1개**로 바로잡는다.

### 마이그레이션 번호

`ls supabase/migrations | tail -1` 확인 → **즉시 파일을 만들어 번호를 선점**한 뒤 내용을 쓴다.

- ⚠️ `migrate.sh`는 **번호 prefix로 적용 여부를 추적**한다. 같은 번호를 서로 다른 내용으로 쓰면 **이미 적용된 것으로 오인해 조용히 건너뛴다**(기록된 사고). 같은 번호가 둘이면 **나중에 만든 쪽이 번호를 옮긴다.**
- 파일명 선점은 이름만 잡을 뿐 **적용 순서를 보장하지 않는다.** 적용은 M-2대로 단독 창구에서.

### changelog

`lib/changelog/entries.ts` 배열 **맨 위에 내 블록만** 추가한다. 다른 항목을 재정렬·병합하지 않는다. 같은 버전 블록이 둘이면 위 버전 재조정을 따라 하나를 옮긴다.

## M-4. 같은 소스를 여러 세션이 고칠 때 — 추가 전용 (하위·상위 호환)

> 세션 A가 함수 시그니처를 바꾸면, 그 함수를 부르는 세션 B의 코드가 **B가 아무것도 안 했는데** 깨진다. 커밋 순서에 따라 누가 깨질지도 달라진다. 서로를 깨지 않는 방향은 **'추가'뿐**이다.

| 대상 | 허용 (추가 전용) | 단독 창구에서만 (배타 claim 필요) |
|---|---|---|
| 함수·모듈 export | 새 함수 추가 / 새 인자는 **선택적 + 기본값** | 시그니처 변경 · 이름변경 · 삭제 |
| 타입·인터페이스 | 새 필드는 **optional** | 필드 삭제 · 필수화 · 타입 축소 |
| API 응답 | 필드 추가 | 필드 제거 · 의미 변경 |
| 컴포넌트 props | **optional** prop 추가 | **필수 prop 추가**(기존 호출처 전부 깨짐) · prop 삭제 |
| DB | **expand**(nullable 컬럼·새 테이블) → backfill → 나중 릴리스에서 contract | 같은 커밋에서 drop · rename |
| 디자인 토큰·클래스 | 새 토큰·클래스 추가 | 기존 토큰 값 변경 · 클래스 삭제 |
| feature flag | 새 플래그는 **기본 OFF**로 넣고 나중에 켠다 | 남의 플래그 기본값 변경 |

- **하위 호환(backward)**: 기존 호출처를 고치지 않아도 그대로 돌아가야 한다. 로직을 새로 쓰면 **기존 함수는 새 함수를 호출하는 얇은 위임으로 남긴다**(§재사용·단일구현 정책과 같은 방향 — 복붙이 아니라 위임).
- **상위 호환(forward)**: 내가 모르는 값이 들어와도 죽지 않게 쓴다. `switch`에 `default:` 필수, 모르는 enum·상태는 **무시하고 통과**, 객체 갱신은 **spread로 보존**(`{ ...prev, mine }`) — 남이 나중에 추가한 필드를 내 코드가 지우지 않는다.
- 삭제·이름변경이 꼭 필요하면 **2단계로 나눈다**: (1) 새것 추가 + 기존것 유지(deprecated 주석) → (2) 모든 호출처 이관이 끝난 뒤 **별도 커밋**에서 제거.

## M-5. 충돌 핫스팟 — 이 파일들은 여러 세션이 동시에 만진다

| 파일 | 왜 위험한가 | 어떻게 |
|---|---|---|
| `package.json` ×2 · 정책 3파일(`CLAUDE.md`·`AGENTS.md`·`GEMINI.md`) | 모든 세션이 커밋마다 만진다 | M-3 낙관적 잠금 |
| `supabase/migrations/NNN_*.sql` | 번호 중복 = 조용한 스킵 | M-3 즉시 선점 |
| `apps/web/lib/changelog/entries.ts` | 모두가 맨 위에 추가 | 내 블록만 append |
| `apps/web/package.json` `test` 목록 | 새 가드마다 append (수기) | 배열 **끝에만** 추가 |
| `apps/web/app/globals.css` | 최대 공유 파일 | 화면 전용 CSS 추가 금지. 토큰은 `:root` 끝에만 |
| `docs/ui-system/INVENTORY.md` | 부품 등재마다 | 해당 표의 행 추가만 |
| `.gitignore` | 도구마다 추가 | 파일 끝에만 append |

- 핫스팟은 **편집 시간을 최소화**한다: 마지막에 열고, 한 번에 고치고, 즉시 커밋한다.
- 핫스팟을 커밋할 땐 **남의 미커밋 줄이 같이 실리는지** 반드시 확인한다 — pathspec 커밋도 그 파일의 작업트리 내용 **전체**를 담는다. 남의 줄이 섞였으면 커밋하지 말고 보고한다.

## M-6. 세션 보드 — 누가 무엇을 들고 있고, 누가 얼마나 나갔나

강제 락이 아니라 **advisory 보드**다. `.sessions/`에 세션별 JSON을 두고 서로 읽는다.
보드 디렉터리는 **스스로 `.gitignore`를 만들어** 커밋되지 않게 한다 — 루트 `.gitignore`는 M-5 충돌 핫스팟이라 건드리지 않기 위해서다.

```bash
# 착수 — 이 작업에서 "쓸" 파일을 먼저 확정해 claim (읽기만 하는 파일은 제외)
node scripts/session.mjs claim <이름> --task "설명" --files "경로,경로"
#   → 다른 세션과 겹치면 경고 + exit code 2. 삭제·시그니처 변경이 필요하면 --exclusive

# 진행 — 노드가 끝날 때마다
node scripts/session.mjs progress <이름> --node "노드명" --done 3 --total 7

# 발견 — 지시받지 않은 버그·개선을 봤을 때 (M-9)
node scripts/session.mjs finding <이름> --what "설명" --where "파일:줄" --sev high --scope outside

# 현황 — 세션별 진척·속도·파일 겹침·발견을 한 화면에
node scripts/session.mjs board

# 종료 — 범위 밖 발견이 남아 있으면 경고한다
node scripts/session.mjs release <이름>
```

- **착수 전에 `board`를 먼저 읽는다.** 겹치면 병렬로 가지 않는다(직렬화하거나 담당 파일을 나눈다).
- **30분 이상 갱신이 없으면 죽은 세션**으로 본다(💤). 그 claim은 무시해도 된다 — TTL 없는 영구 claim은 보드를 쓸모없게 만든다.
- 속도(`노드/h`)와 🥇 표시는 **세션 간 비교용 지표**다. 사용자가 어느 세션이 막혀 있는지 한눈에 보게 하는 것이 목적이지, 속도를 위해 검증을 건너뛰라는 뜻이 **아니다**.

## M-7. 그래프 분해 — 병렬의 단위는 '파일 소유권'이다

1. 착수 시 작업을 노드로 쪼개고, **각 노드가 쓸 파일 목록을 먼저 확정**한다. 파일을 모르면 아직 분해가 안 된 것이다.
2. 파일이 **겹치지 않는 노드만** 병렬로 돌린다. 겹치면 병렬이 아니다 — 직렬화하거나, 겹치는 부분을 `lib/`의 SSOT 모듈로 **먼저 분리**해 소유권을 나눈 뒤 병렬로 간다.
3. join 지점에서 **각자 자기 범위로 검증**한다(남의 진행 중 코드가 내는 오류로 판정하지 않는다). 통합 검증은 마지막에 한 번.
4. 커밋도 노드 단위로 쪼갠다. 노드 하나가 끝나면 바로 pathspec 커밋 — 오래 들고 있을수록 충돌 창이 넓어진다.

## M-8. Codex 협업 — 구현이 아니라 기획 단계의 검토자

> Codex를 같은 트리에서 구현에 붙이면 M-1 사고가 그대로 재현된다. 반면 **기획 단계**에서는 다른 모델의 시각이 실제로 값을 만든다. 그리고 DOMANGCHA 불변 규칙대로 **만든 사람이 유일한 검토자가 될 수 없다.**

- Codex가 사용 가능하면(`codex exec`) **기획·설계안을 먼저 검토받는다.** 읽기 전용으로 띄워 파일을 못 고치게 한다:
  ```bash
  codex exec -s read-only "…설계안 A~G… 각각 (1)이 저장소에서 통하는가 (2)빠진 위험 (3)대안"
  ```
- 받은 의견은 **채택/반려를 이유와 함께 기록**한다. **반려도 기록한다** — 반려 이유가 다음 세션의 근거가 된다.
- 구현은 한 세션이 맡는다. Codex에 구현을 넘길 거면 **담당 파일을 보드에 claim하고 그 세션은 해당 파일을 만지지 않는다.**
- Codex가 없으면 그 자리를 다른 세션이나 리뷰 에이전트가 맡는다. **검토자 없이 넘어가지 않는다.**

## M-9. 실화면 검증 중 발견한 '지시받지 않은' 결함 — 넘어가지 않는다

> 화면을 보다 보면 지시받지 않은 결함이 반드시 눈에 띈다. "시키지 않았으니 넘어간다"가 쌓이면 **아무도 안 고치는 결함**이 영구화된다. 동시에 dev 서버는 **모든 세션이 공유**하므로, 내가 보는 화면에 다른 세션의 저장 중간 상태가 섞여 있을 수 있다 — 남의 결함을 내 것으로 오진하는 일도 막아야 한다.

**발견하면 반드시 분류하고, 어떤 분류든 기록한다. 조용히 넘어가는 선택지는 없다.**

| 분류 | 판정 | 조치 |
|---|---|---|
| ① 내 변경이 만든 회귀 | 내가 이번에 건드린 경로에서 발생 | **즉시 고친다** — 같은 커밋에 포함 |
| ② 내 작업 범위 안의 기존 결함 | 지금 내가 만지는 파일·화면인데 원래 있던 문제 | **같이 고친다** — 단 **커밋은 분리**하고 메시지에 지시 외 발견임을 밝힌다 |
| ③ 범위 밖 | 다른 화면 · 다른 세션이 claim한 파일 | **고치지 않는다** — `finding --scope outside` + **사용자에게 보고** |
| ④ 남의 세션이 만든 중간 상태 | 내가 안 건드린 파일이 방금 바뀌어 있음 | **내 결함으로 오진하지 않는다** — 보드에서 소유 세션 확인 후 기록만 |

- **①이라도 그 파일을 다른 세션이 claim 중이면 즉시 고치지 않는다.** 보드 확인이 항상 선행이다.
- **③·④는 보고가 의무**다. 세션 종료 보고에 **"발견 N건"을 반드시 포함**한다. 0건이면 0건이라고 말한다. 침묵은 "없었다"가 아니라 **규칙 위반**이다.
- 기록 형식: **무엇이 / 어디서(`파일:줄` 또는 URL) / 재현 방법 / 심각도 / 제안**. 이 5개가 없으면 다음 사람이 다시 조사해야 한다.
- 판정이 애매하면 ③으로 둔다. 고치는 쪽보다 **기록하고 묻는 쪽**이 항상 안전하다.

## M-11. 세션 완결 책임 — 시작한 세션이 끝까지 맡는다

> **왜**: 여러 세션이 동시에 돌면 "누군가 마무리하겠지"가 생긴다. 그런데 다른 세션은 **내 작업을 모른다.** 반쯤 된 코드를 트리에 남기고 끝내면, 그것을 본 다른 세션이 **자기 결함으로 오진**하거나(M-9 ④), 그 위에 쌓아 올려 되돌리기 어려워진다. 세션 경계는 **작업 경계가 아니다** — 시작한 세션이 끝내야 한다.

### 완료의 정의 (Definition of Done) — 하나라도 빠지면 미완이다

| # | 항목 | 빠지면 생기는 일 |
|---|---|---|
| 1 | 구현이 **지시 범위 전부**를 덮는다 | 일부만 된 기능이 된 것처럼 보인다 |
| 2 | 관련 검증 통과 (`tsc` · `lint` · 관련 테스트 · `design:check`) | 다음 세션이 내 오류를 자기 것으로 디버깅한다 |
| 3 | **실제 렌더 경로**에서 화면 확인 | "고쳤는데 화면 그대로" 사고 |
| 4 | 발견 처리 완료 (M-9 ①②는 수정, ③④는 기록) | 아무도 안 고치는 결함이 영구화된다 |
| 5 | **정리** — 커밋 권한이 있으면 pathspec 커밋(M-1), 없으면 트리를 **빌드되는 상태**로 남기고 미커밋 목록을 보고 | 반쯤 된 상태를 남이 오진하거나, `stash`에 쓸려 사라진다 |
| 6 | 사용자 보고 (한 것 · 못 한 것 · 발견 N건) | 사용자가 무엇이 끝났는지 모른다 |
| 7 | `session.mjs release` | 남이 그 파일을 30분간 못 잡는다 |

### 넘기지 않는다

- **"다음 세션이 하겠지"로 끝내지 않는다.** 다른 세션은 내 작업의 존재조차 모른다.
- **다른 세션의 미완 작업을 대신 끝내주지 않는다.** 의도를 모른 채 손대면 그 세션의 설계를 망친다. 보이면 M-9 ③으로 기록하고 사용자에게 알린다.
- **중간 상태로 트리에 두고 떠나지 않는다.** 끝내지 못할 것 같으면 **동작하는 최소 단위까지만** 만들어 커밋하고, 나머지를 명시적으로 인계한다.

### 정말 못 끝낼 때 — 침묵 종료는 금지

끝내지 못하는 것 자체는 문제가 아니다. **말없이 떠나는 것**이 문제다. 다음 3개를 남긴다.

1. **보드에 남긴다** — `progress`로 현재 노드와 `done/total`을 실제 값으로 갱신
2. **사용자에게 보고한다** — 무엇이 남았는지 · 왜 못 했는지(막힌 지점) · 다음 단계는 무엇인지
3. **코드를 안전한 상태로 둔다** — 빌드가 깨진 채 두지 않는다. 되면 커밋, 안 되면 되돌려 원상 복구

> **판단 기준**: "지금 내가 사라져도 다른 사람이 이 상태에서 이어받을 수 있는가?" 아니면 아직 끝난 게 아니다.

## M-12. "남은 것"은 없다 — 지시 범위를 스스로 줄이지 않는다

> **왜**: 일을 단계로 쪼개는 것은 **순서를 잡기 위한 도구**다. 그런데 앞 단계만 하고 뒤를
> "남은 것"이라 부르며 보고를 끝내면, 도구였던 단계가 **지시 범위를 자르는 선**이 된다.
> 사용자는 단계를 나눠 시킨 적이 없다.
>
> **실제 사고 (2026-08-16, v0.7.480)**: 콘텐츠 인텔리전스 재설계를 6단계로 기획한 뒤
> 단계 0만 구현하고 "남은 것: 단계 1~6"으로 보고했다. 사용자 지적 — **"남은 것이라는 것은 없어
> 방법을 찾아서 진행해 절대 멈추지마"**. M-11이 *세션 경계*로 자르는 것을 막았다면,
> M-12는 **내가 만든 단계로 자르는 것**을 막는다.

### 규칙

| | 규칙 |
|---|---|
| **1** | **지시 범위 = 완료 범위.** 내가 세운 단계·우선순위·P0/P1은 **순서**이지 "이번 몫의 경계"가 아니다 |
| **2** | **막히면 형태를 바꿔 본다.** 멈추기 전에 "되돌릴 수 있는 형태"로 만들 수 없는지 먼저 확인한다 |
| **3** | **진짜 멈출 것은 셋뿐.** 그 외에는 진행한다 |
| **4** | **보고에 "남은 것"을 쓰지 않는다.** 못 한 것이면 "못 한 것"이라 쓰고 이유와 필요조건을 적는다 |
| **5** | **분량은 멈출 이유가 아니다.** 커밋을 나눌 이유다(M-7) |

### 규칙 2 — 형태를 바꾸는 법 (막혔을 때 먼저 볼 표)

| 막힌 형태 | 바꾼 형태 | 왜 통과되나 |
|---|---|---|
| 물리 삭제 / 행 병합 | **소프트 삭제 + 복구 경로**(`deleted_at`·`merged_into_id`) | 되돌릴 수 있으면 파괴적이지 않다 |
| 기존 동작 전면 교체 | **플래그 뒤 신규 경로**(기본 OFF → 검증 후 ON) | 회귀 위험이 0이다 |
| 파괴적 마이그레이션 | **expand → backfill**(contract는 다음 판) | 기존 읽기 경로가 안 깨진다 |
| 외부 API 쓰기 | **읽기만으로 검증 + 쓰기는 드라이런 로그** | 외부로 나가지 않는다 |
| 운영 데이터 실험 | **투입 → 검증 → 원상 복구**(같은 세션 안에서) | 흔적이 남지 않는다 |

### 규칙 3 — 정말 멈춰야 하는 셋

1. **되돌릴 수 없는 운영 데이터 변경** — 물리 삭제·복구 불가 병합·이력 소실
2. **외부로 나가는 것** — `push` · 배포 · 알림/메일 발송 · 외부 API 쓰기
3. **사용자만 아는 사실이 필요한 결정** — 사업 판단, 우선순위, 어느 계정부터 열지

> 셋 중 하나에 걸리면 **그 하나만** 멈추고 사용자에게 승인 요청을 남긴 뒤,
> **나머지는 끝까지 간다.** 하나 때문에 전체를 세우지 않는다.
