# 트렌드 › 시장 탭 — 정체 파악과 재설계 기획

- 작성: 2026-08-16 · 기준 버전 v0.7.487 · **구현 없음(파악·기획 전용)**
- 대상: `/ci/trends?tab=market` (R04 트렌드의 첫 탭)
- 판정 방법: 소스 전수 읽기 + **운영 DB 실측** + 설계 문서 대조

---

## 0. 한 줄 결론

> **부품은 표준을 지켰다. 그런데 이 화면은 "시장"이 아니다.**
> 실측하면 표본의 **99%가 채널 한 곳**(추성훈 310/313건)이다. 한 계정의 업로드 습관을
> "시장"이라 부르며 보여주고 있다. 게다가 화면 위쪽 조건(28일·주제)이 **아래 절반에는 안 먹혀서**,
> 위는 18건 · 아래는 313건으로 **한 화면에 두 개의 모집단**이 공존한다.
> 그리고 무엇보다 — **이 화면은 사용자가 무슨 결정을 내려야 하는지 말하지 않는다.**

---

## 1. 먼저: 이 화면은 원래 뭘 하는 곳인가

### 1-1. 설계 문서에 **이 화면의 정의가 없다**

| 문서 | 내용 |
|---|---|
| `00-integration-decisions.md:45` | `trends/  R04 트렌드 (탭 4)` — **라우트 한 줄이 전부** |
| `03-screen-a01-performance.md:61` | "탭 2 — 시장 대비" — 이건 **성과(A01) 화면**의 탭이지 R04가 아니다 |

즉 **R04 트렌드는 화면 설계서 없이 만들어졌다.** 다른 화면(A01)에는 레이아웃·모집단·빈 상태 문구까지
정의돼 있는데 R04만 없다. "표준도 아니고 뭐지?"라는 인상의 뿌리가 여기다 —
표준 **부품**은 썼지만 표준 **설계 절차**를 안 거쳤다.

### 1-2. 코드에서 역추적한 실제 의도

시장 탭이 그리는 것은 네 덩어리다.

| 섹션 | 무엇을 | 모집단 |
|---|---|---|
| 플랫폼별 | 유튜브·틱톡별 건수·비중·평소 대비 중앙값 | 기간·주제 필터 **적용** |
| 포맷별 | 숏폼·롱폼별 같은 지표 | 기간·주제 필터 **적용** |
| 언제 통했나 | 계절·시간대·요일별 같은 지표 | **필터 없음(전체)** ← 모순 |
| 많이 올린 채널 | 채널별 건수 | 기간·주제 필터 **적용** |

읽어보면 의도는 분명하다: **"내가 지켜보는 계정들을 통틀어, 어떤 조건에서 잘 통하나"**.
채널 상세의 "이 계정에서 왜 잘 됐나"를 **시장 전체로 확대한 것**이다.

**그런데 그 의도가 화면에 안 나타난다.** 이유는 §3에서.

## 2. 실측 — 숫자가 말하는 것

```
코퍼스 313건 / 기여 채널 4곳 / 최근 28일 18건

추성훈 ChooSungHoon   310건  99.0%
officialpsy             1건   0.3%
TikTok                  1건   0.3%
jawed                   1건   0.3%
```

화면이 "요일: 금요일 165건 · 평소 대비 1.3배 / 화요일 4건"이라고 말할 때,
그건 시장의 성질이 아니라 **추성훈 채널이 금요일에 많이 올린다**는 사실이다.
"저녁 248건(79%)"도 마찬가지다.

**이 화면은 지금 시장을 관찰하고 있지 않다. 한 사람의 업로드 스케줄을 관찰하고 있다.**

## 3. 결함 목록

### P0-1. 한 화면에 모집단이 둘이다 (숫자가 서로 안 맞는다)

- 상단 근거 문구: **"28일 기준, 표본 18건"**
- 하단 "언제 통했나": **"312/313건 판정"**

원인은 한 줄이다 — `getTimingOverview(workspaceId)`는 **기간도 주제도 안 받는다**
(`lib/ci/queries/trends.ts:250`). 조건 바를 7일로 바꿔도 아래 절반은 **그대로다.**

사용자가 겪는 것: 기간을 바꿨는데 숫자가 안 변한다 → "고장인가?"
그리고 위아래 숫자가 20배 차이 나는데 **화면은 그 이유를 말하지 않는다.**

### P0-2. 표본이 채널 1곳이어도 "시장"이라고 말한다 — 같은 제품 안에서 기준이 갈린다

| 탭 | 채널 다양성 게이트 | 근거 |
|---|---|---|
| **성공 공식** | **채널 5곳 미만이면 공식을 만들지 않는다** | `PATTERN_MIN_CHANNELS = 5` |
| **떡상** | 비교군 8건 미만이면 배수를 안 낸다 | `OUTLIER_MIN_BASELINE = 8` |
| **시장** | **없음** | 구간 표본 3건이면 배수를 낸다(`TIMING_MIN_SAMPLE = 3`) |

성공 공식은 "한 채널의 우연을 공식으로 승격하지 않으려고" 채널 5곳을 요구한다.
**시장 탭은 정확히 그 우연을 시장이라고 부른다.** 같은 제품이 같은 위험에 대해 다른 답을 낸다.

### P0-3. 결정을 돕지 않는다 — "나열"이지 "대조"가 아니다

화면이 말하는 것: `봄 0.7배 · 여름 1.0배 · 가을 1.9배 · 겨울 1.1배`
사용자가 알고 싶은 것: **"그래서 나는 뭘 해야 하지?"**

채널 상세의 "왜 잘 됐나"는 **잘된 것과 평소를 대조**해 `"토요일 게시 — 잘된 쪽 50%, 평소 17%"`처럼
읽는 즉시 행동이 떠오르는 문장을 낸다. 시장 탭은 같은 데이터로 **표만 그린다.**

같은 질문에 대한 구현이 **두 벌**이고, 좋은 쪽이 나쁜 쪽에 적용되지 않았다.

### P1-4. 정보 위계가 없다 — 표 5개가 평평하게 나열된다

전부 같은 모양(`구간 · 건수 · 평소 대비 중앙값`)의 표가 세로로 이어진다.
어느 것이 중요한지, 어디부터 읽어야 하는지 화면이 말하지 않는다.
부품 위반은 아니지만(§2-6 `ListSurface` 준수), **정보 설계가 없다.**

### P1-5. "평소 대비 중앙값"이 무슨 뜻인지 화면이 설명하지 않는다

각 게시물의 "자기 채널 평소 대비 배수"를 모아 중앙값을 낸 것이다.
그런데 채널이 1곳이면 이 값은 **그 채널 내부의 분포**일 뿐이다.
용어 툴팁도 없고, 무엇 대비인지도 안 밝힌다.

### P2-6. 빈 상태 문구가 현실과 안 맞는다

`"관심 채널을 등록하면 그 채널의 게시물이 모여 시장 그림이 만들어집니다"` —
채널 **1곳**만 등록해도 이 문구는 사라지고 "시장"이 그려진다. 문구가 약속한 조건을 화면이 안 지킨다.

## 4. 재설계 기획

### 원칙 — 이 화면이 답해야 하는 질문 하나

> **"내가 지켜보는 시장에서, 지금 무엇이 통하고 있나. 그래서 나는 뭘 해야 하나."**

이 질문에 답하지 못하는 요소는 전부 지운다.

### 4-1. 정직성 먼저 — 근거가 없으면 "시장"이라 부르지 않는다

**표본 구성을 화면 맨 위에 밝힌다.**

```
28일 기준 · 게시물 18건 · 채널 4곳
⚠ 이 중 99%가 채널 한 곳(추성훈)입니다. 아래 수치는 시장이 아니라 그 계정의 성향에 가깝습니다.
```

**채널 다양성 게이트를 시장 탭에도 적용한다** — 성공 공식과 같은 선(`PATTERN_MIN_CHANNELS = 5`).

| 기여 채널 | 화면 |
|---|---|
| 5곳 이상 | "시장" 전체 표시 |
| 2~4곳 | 수치는 보여주되 **"시장이라 부르기엔 이릅니다"** 배너 + 채널 추가 유도 |
| 1곳 | 시장 섹션 대신 **"아직 시장이 아닙니다"** — 그 채널의 계정 분석으로 안내 |

> 근거: 이미 제품이 그 기준을 갖고 있다(§3 P0-2 표). 새 기준을 만드는 게 아니라 **있는 기준을 마저 적용**한다.

### 4-2. 모집단을 하나로 — 조건 바가 화면 전체를 지배한다

`getTimingOverview(workspaceId)` → `getTimingOverview(workspaceId, { windowDays, topicId })`.
플랫폼별·포맷별과 **같은 필터**를 통과시킨다.

- 근거 문구는 **화면에 하나만** 둔다. 섹션마다 다른 모집단을 쓰지 않는다.
- 만약 어떤 섹션이 다른 창을 써야 한다면(예: 계절은 1년이 필요) **그 섹션에 그 이유를 적는다.**
  침묵한 채 다른 숫자를 보여주지 않는다.

> 계절 분석은 28일 창에서 의미가 없다(한 계절만 들어온다). 두 선택지 중 하나:
> ⓐ 계절 섹션을 **1년 고정**으로 하고 "계절은 최근 1년 기준입니다"를 명시
> ⓑ 창이 90일 미만이면 계절 섹션을 **아예 숨긴다**
> → **ⓑ 권장.** 보여줄 수 없는 것을 보여주는 것보다 없는 편이 정직하다.

### 4-3. 나열을 대조로 — 이미 있는 SSOT를 재사용한다

`lib/ci/analysis/account-contrast.ts`가 이미 "잘된 것 vs 평소"를 대조해
읽는 즉시 행동이 떠오르는 문장을 만든다. **시장 탭이 그것을 그대로 쓴다.**

```
지금 시장에서 통하는 것 (28일 · 채널 6곳 · 게시물 142건)
  · 숏폼 — 잘된 쪽 71%, 평소 34%          근거 24건
  · 저녁 게시 — 잘된 쪽 58%, 평소 29%      근거 19건
  · 길이 — 잘된 쪽 약 48초, 평소 약 95초    근거 31건
```

- 대조 임계(`MIN_WINNERS 3` · `MIN_BASELINE 5` · `MIN_LIFT 1.5`)를 그대로 승계한다.
- 차이를 못 찾으면 **"뚜렷한 차이를 찾지 못했습니다"**라고 말한다(억지 공식 금지).
- **기존 표는 지우지 않고 "자세히" 아래로 내린다** — 근거를 확인하려는 사용자를 위해 남긴다.

> 이것이 이 기획의 핵심이다. 새 분석 엔진을 만들지 않는다.
> 같은 질문에 대한 **두 번째 구현을 없애고 좋은 쪽 하나로 모은다**(SSOT).

### 4-4. 화면 구조 — 위에서부터 읽으면 결론 → 근거

```
┌─ 트렌드 › 시장 ────────────────────────────────┐
│ [주제 전체 ▾] [기간 28일 ▾]                     │
│ 28일 · 채널 6곳 · 게시물 142건                   │  ← 근거 하나. 화면 전체에 적용.
├────────────────────────────────────────────────┤
│ 지금 시장에서 통하는 것            ← 결론(대조)  │
│   · 숏폼 — 잘된 쪽 71%, 평소 34%                │
│   · 저녁 게시 — 잘된 쪽 58%, 평소 29%           │
│   (근거 부족하면 "왜 아직 말할 수 없는지")        │
├────────────────────────────────────────────────┤
│ 어디에 몰려 있나                  ← 분포 1개 표 │
│   플랫폼 · 포맷을 한 표에 합침                   │
├────────────────────────────────────────────────┤
│ ▸ 자세히 보기 (접힘)              ← 근거 확인용 │
│   계절 · 시간대 · 요일 · 많이 올린 채널          │
└────────────────────────────────────────────────┘
```

- 표 5개 → **결론 1블록 + 표 1개 + 접힌 상세**
- "언제 통했나"의 세 표는 §4-3의 대조에 흡수되고, 원본 표는 상세로 내린다

### 4-5. 용어 — 화면이 스스로 설명한다

- `평소 대비 중앙값` 옆에 ❓ 툴팁: *"각 게시물이 자기 채널 평소보다 몇 배 나왔는지를 모아 중앙값을 낸 값입니다."*
- 정책 §3-1대로 설명문은 **툴팁·드로어**에 넣고 표 위아래에 문단을 깔지 않는다.

## 5. 단계 (구현 시)

| 단계 | 내용 | 되돌릴 수 있나 |
|---|---|---|
| **1** | `getTimingOverview`에 기간·주제 필터 추가 → 모집단 통일 | 예 (인자 추가) |
| **2** | 표본 구성(채널 수·최대 채널 비중) 노출 + 채널 다양성 게이트 | 예 (표시 계층) |
| **3** | `buildAccountContrast`를 시장 코퍼스에 적용해 "지금 통하는 것" 블록 신설 | 예 (신규 섹션) |
| **4** | 표 재배치(결론 → 분포 → 접힌 상세) + 용어 툴팁 | 예 (레이아웃) |
| **5** | 가드: 모집단 단일성 · 게이트 존재 · 대조 SSOT 재사용을 정적 테스트로 잠금 | 예 |

**전부 되돌릴 수 있다.** 마이그레이션 없음, 데이터 변경 없음, 외부 발신 없음 —
M-12 기준의 "멈춰야 하는 셋"에 해당하는 것이 없다.

---

## 6. 하지 않을 것

- **새 분석 엔진을 만들지 않는다.** `account-contrast`가 이미 답을 낸다.
- **표를 예쁘게만 고치지 않는다.** 문제는 모양이 아니라 **모집단·기준·결론 부재**다.
- **채널 1곳으로 "시장"을 말하지 않는다.** 데이터가 자랄 때까지 그렇다고 말한다.
- **숫자를 지어내지 않는다.** 근거가 없으면 없다고 말하는 기존 원칙을 그대로 지킨다.
