## 2 능력 여덟과 공통 계약

능력: 추출 요약 판정 제안 생성 질의응답 전사 의미검색

결과 계약 (모든 능력이 같은 모양)
- 값
- 근거 (원문 블록 번호와 글자 자리)
- 확신
- 출처 (공급자 모델 시각)
- 상태 (후보 확정 사람이고침)
- 고친 흔적
- 계약 판 번호

세 층
- 아래층 관문: 시간 제한 JSON 복구 폴백 개인정보 가림 비용 전송 기록
- 가운데 능력: 여덟 가지
- 위층 부품: AI 값 근거보기 후보목록 제안대조 생성고지 고친흔적 물어보기 진행상태

능력과 부품의 짝 (가드로 강제)
- 추출 -> 후보 검수 없이 확정 금지
- 생성 -> 미리보기 없이 저장 금지
- 판정 -> 근거 없이 표시 금지
- 질의응답 -> 출처 없이 답변 금지

## 3 패키지 경계

자르는 기준: AI 라는 일반 문제면 패키지 안, 우리 회사 사실이면 저장소 안

패키지 (packages/* 신설, pnpm-workspace 에 추가, 발행은 나중)
- core 능력 여덟, 결과 계약, 상태 머신
- gateway 시간제한 JSON복구 폴백 가림 비용 기록창구
- providers 공급자 어댑터
- catalog 카탈로그 스키마와 필터 검증기 (내용물 없음)
- react AI 부품 한 벌
- guard 검사 규칙 (러너는 쓰는 쪽이 등재)

저장소
- 어댑터 한 파일 (공급자 초기화, 용어집 라벨 주입, 키 읽기, 기록 연결)
- 카탈로그 데이터 (개체 칸 관계 범위 민감도)
- 능력별 프롬프트

부품은 한글을 한 글자도 갖지 않는다, 쓰는 쪽이 라벨을 준다
패키지 안 한글 0건과 경계 침범을 가드로 잠근다

## 4 정책 세 겹

1겹 타입: AI 값은 관문 밖에서 못 만들고 부품은 AI 값만 받는다
2겹 정적 가드 (본선): 능력과 부품의 짝 표를 대조, 서버 생성 화면 렌더 분리는 등재 파일로 (주석 면제 금지)
3겹 개발 중 경고: AI 값을 만들었는데 화면이 안 그리면 경고

기존 위반 34건은 즉시 차단하지 않고 기준선을 둔다, 늘면 막고 줄면 따라 내린다
기존 가드 34파일 211검사 위에 얹는다

## 5 자동 배치

- 공용 렌더러 = 주력 (값의 종류가 부품을 정한다, 날짜 칸 금액 칸 선례)
- 타입 강제 = 자물쇠
- 레이아웃 슬롯 = 상태 UI 한정
- 자동 수정 = 자작 26개 이관 1회만
- 뼈대 생성 = 채택 안 함

## 6 계약 판 관리

- 저장할 때 계약 판 번호를 같이 넣는다
- 읽을 때 옛 판을 새 판으로 올리는 사다리 하나
- 일괄 이관 금지, 읽고 쓰는 길이 지나갈 때만 다시 저장
- 못 올리는 칸은 버리지 않고 이전 형식으로 표시하고 원문 보존

## 7 RFP 네 층

| 층 | 능력 | 답하는 질문 | 지금 |
|---|---|---|---|
| 1 사실 | 추출 | 무엇이라 쓰여 있나 | 돈다 |
| 2 검증 | 판정 | 문서끼리 어긋나지 않나 | 모듈 3개 중 1개만 결선 |
| 3 판단 | 판정 | 할 수 있나 위험한가 | 규칙 저장이 안 됨 |
| 4 생성 | 생성 | 제안서를 어떻게 쓰나 | 목차까지 나옴 |

- 2층은 어긋나면 사실로 확정하지 않고 어긋남으로 표시한다
- 3층은 규칙으로 먼저 거르고 애매한 것만 AI 가 본다
- 특정 업체에 유리하다는 단정 금지, 경쟁 제한 의심으로만 표기
- 층을 나누는 이유는 지금 한 덩어리라 어디가 틀렸는지 말할 수 없기 때문

## 10 등록과 설정 화면 열넷

있는데 저장이 안 되는 것 넷
- 이상 조항 규칙 (스위치는 있고 저장 창구가 없다)
- AI 공급자 등급
- 사용량과 한도 (월 예산 상한 설정 불가)
- 전송 기록 (지금 0건)

아예 없는 것 여섯
- 문서 등급 편집 (DOC_CLASS_POLICY 가 코드 상수)
- 조직과 구성원 (rfp_orgs rfp_org_members rfp_invites 표는 있고 화면 없음)
- 요금제 (rfp_plans)
- 알림 (rfp_notifications 창구는 있고 화면 없음)
- 수집 주기 (지금 켜기 끄기만)
- 리포트 파생 필드 (rfp_report_schemas 소비 코드 0곳)

공통 설정 넷
- 공공데이터포털 서비스 여섯의 신청 상태와 일일 한도와 마지막 결과
- AI 공급자와 모델 (능력별 모델 선택 추가)
- 카탈로그 (어시스턴트가 볼 개체와 칸, 민감한 칸 잠금)
- 능력별 프롬프트 (화면에서 고치고 판 보존)

설정값은 env 추가 대신 DB 저장과 UI 관리

## 11 순서

1 관문과 계약을 패키지로 승격 + 벤더 직접 호출 34건에 기준선
2 계약 판 번호 동봉 (첫 저장 전이 가장 쌈)
3 AI 부품 한 벌과 짝 가드를 같이
4 개인정보가 나가는 곳부터 관문으로 (명함 리드 딜메모 일일업무 주간보고 회의전사)
5 저장 안 되는 설정 넷 고치고 없는 여섯 신설
6 RFP 용어를 용어집으로 (개체 여덟 등재)
7 RFP 네 층 결선
8 공공데이터포털 다섯 서비스 개방 (사전규격 먼저)
9 자작 부품 26개 이관 + 카탈로그 신설

왜 이 순서인가
- 관문이 첫째인 이유는 뒤 단계가 전부 그것을 전제하기 때문
- 판 번호가 둘째인 이유는 저장이 시작되면 값이 계속 쌓이기 때문
- 설정이 다섯째로 앞선 이유는 지금 사용자를 속이고 있기 때문 (켜진 것처럼 보이는데 저장 안 됨)
- 용어가 여섯째인 이유는 카탈로그와 어시스턴트가 그것을 전제하기 때문

## 12 놓치기 쉬운 것 열둘

1 서버에서 화면으로 넘어갈 때 타입 표식이 지워진다 (화면 부품 155 대 서버 부품 26), 경계 규약을 계약에 처음부터
2 흘려보내기를 계약에 안 넣으면 부품을 다시 만든다, 중간값 상태를 첫 판에
3 대기열이 4곳뿐이라 계약이 동기 전제로 굳는 중, 상태 머신을 먼저 박는다
4 가림이 나가는 쪽만 있고 들어오는 쪽이 없다, 응답 검사 자리를 관문에
5 가드를 그대로 팔 수 없다, 규칙 함수와 검사 도구용 규칙 두 형태로
6 정답 자료와 프롬프트에 사내 실데이터가 섞여 있다, 거르는 검사를 배포에 상설
7 카탈로그는 칸 단위인데 권한은 행 단위, 범위 결정 자리가 없으면 권한 밖 행이 샌다
8 기록 창구를 선택으로 두면 조용히 0건이 된다, 기본값 no-op 금지
9 확정 상태와 고친 흔적이 앱에만 있으면 계약이 종이가 된다, 저장 창구를 패키지가 정의
10 공공데이터포털은 신청이 여섯 번이고 한도가 따로, 넘기면 수집이 조용히 멈춘다
11 사전규격은 확정이 아니다, 추정 표시와 갱신 자리 필요
12 능력이 늘 때 부품과 카탈로그가 같이 안 늘면 다시 갈린다

## 13 지켜야 할 제약

- git push 금지, 커밋까지만
- scripts/migrate.sh 는 운영 DB 공유이고 되돌릴 수 없어 사용자 승인 필요
- 설정값은 env 추가 대신 DB 저장과 UI 관리
- 비밀 금지, diff 에 키 토큰 비밀번호 없음
- 테스트 격리, 실데이터 오염 금지
- Gemini 무료 키 사용 금지
- AI 생성 고지를 리포트 어시스턴트 내보내기에 전부
- 특정 업체에 유리하다는 단정 금지, 경쟁 제한 의심으로만
- 화면 한글 직접 금지, @/lib/terms 용어집 SSOT
- 문서는 개조식, 마침표 없는 종결, 가운뎃점 미사용, 이모지 미사용, 전각 대시 미사용, 한자 금지
- loop pass 는 git add -A 라 --no-commit 후 내 경로만 add
