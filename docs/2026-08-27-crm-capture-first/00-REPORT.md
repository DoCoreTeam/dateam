# 1차 릴리스 · 손이 먼저 닿는다

**약 2일 · 마이그레이션 없음 · 선행 없음 · 파일 4개**

## 지금은

`/crm/today`는 **읽기 전용**이다(`TodayClient.tsx` 276줄 전체에 새 기록을 만드는 진입 없음).
그리고 맨 위를 「시작하기」 체크리스트가 차지하는데, 4번째 항목이 **셋업이 아니라 운영 지표**라
딜을 새로 만들 때마다 **완료가 풀려서 다시 뜬다.** (물어보신 그 카드다)

```ts
// lib/crm/services/setup-progress.ts:110
done: deals > 0 && unplanned === 0   // ← 영업하는 한 계속 0↔1 을 오간다
```

## 이렇게 고친다

1. **「시작하기」를 3단계로 줄인다.** 4번째(다음 할 일)는 바로 아래 배너가 이미 하고 있어 **중복**이다.
   빼면 완료가 진짜 완료가 되어 카드가 **영영 사라진다.**
2. **그 자리에 「지금 회의 중」 상자를 놓는다.** 버튼 셋 — 녹음 시작 · 그냥 적기 · 붙여넣기.
3. 오늘 캘린더에 회의 일정이 있으면 **그것을 후보로 보여 준다.** 누르면 그 일정에 이어붙인다.

> **새로 만드는 것이 거의 없다.** 작업대(`MeetingWorkbench`)·녹음 프로바이더(`AppShell.tsx:124`)·
> 제목·시각을 안 묻는 진입(`start-meeting.ts`)이 **이미 다 있다.**
> 1차는 **기존 호출 셋을 첫 화면으로 끌어올리는 작업**이다.

```
신설   components/crm/MeetingIntakeBox.tsx

수정   lib/crm/services/setup-progress.ts       — 4단계 제거
수정   lib/crm/services/setup-progress.test.ts  — "완료 후 다시 미완이 되지 않는다" 단정
```

# 2차 릴리스 · 회의가 끝나면 AI가 채우거나 묻는다

**약 3일 · 마이그레이션 없음 · 선행 1차 · 파일 6개**

## 지금은

- **"회의가 끝났다"를 시스템이 모른다.** `crm_meeting.endedAt`은 스키마·API에 다 있는데 **채우는 경로가 없다**(`start-meeting.ts:70`).
- **버튼이 둘이다.** 「정리」와 「5축 추출」이 따로 돌아 사람이 두 번 눌러야 한다.
- **AI가 모르는 것에 대해 아무 말도 안 한다.** 제안 축 5개(`WHO WHAT WHERE RISK NEXT`)가 전부 *값을 아는 경우*의 축이다.

## 이렇게 고친다

### ① 버튼 하나 — 「회의 끝내기」

누르면 셋이 한 번에: `endedAt = now()` → 녹음 정지 + 마지막 구간 flush → **정리 + 5축 + 빈칸 점검 일괄.**

### ② 6번째 축 `ASK` 신설 — AI가 묻는 자리

```prisma
enum CrmSuggestionAxis { WHO WHAT WHERE RISK NEXT ASK }   // 추가 전용
```

```json
{ "axis": "ASK", "targetType": "deal", "field": "closeDate",
  "proposedValue": {
    "question": "언제 계약 예정인지 회의에서 안 나왔어요. 목표 시점이 있나요?",
    "why": "이 딜만 마감일이 비어 있어 예측에서 빠집니다" } }
```

| AI 상태 | 축 | 결과 |
|---|---|---|
| 값을 안다 · 근거 있다 | `WHO/WHAT/WHERE` | 제안 카드 (지금과 같음) |
| 모른다 · **비면 안 되는 칸**이다 | **`ASK`** | **질문 카드** — 그 자리에서 입력 |
| 모른다 · 안 비어도 된다 | — | **아무 말 안 한다** |

> **"비면 안 되는 칸"은 이미 정해져 있다.** `data-check.ts`의 빈칸 규칙과 `verify.ts`의 확정 가능 필드 목록이
> 그 목록이다. **재사용한다 — 새 목록을 만들지 않는다.**
>
> 예외 하나 — 근거 없는 제안을 폐기하는 규칙(`dropUngrounded`)은 `ASK`에 적용하지 않는다.
> `ASK`의 근거는 발화가 아니라 **빈칸 그 자체**이기 때문이다.

### ③ AI가 아는 것을 넓힌다

지금 넘기는 것은 회사·딜·단계이름·우리 사람 넷(`extract-context.ts`). 셋을 더한다.

| 더할 것 | 안 주면 |
|---|---|
| 이 회사와의 **최근 미팅 3건 요약** | "지난번에 말한 그 건"을 못 알아듣는다 |
| 이 딜의 **열린 할 일** | 이미 있는 할 일을 또 제안해 인박스가 찬다 |
| 이 회사의 **인물 명단** | 등록된 사람을 새 인물로 또 제안한다 |

```
수정   prisma/schema.prisma                        — CrmSuggestionAxis 에 ASK
신설   lib/crm/services/ask-suggest.ts             — 빈칸 → 질문 (data-check 규칙 재사용)
수정   lib/crm/services/extract-context.ts         — 미팅3 · 할일 · 인물
수정   lib/crm/services/meeting.ts                 — endedAt + 정리 일괄
수정   components/meeting/MeetingWorkbench.tsx     — 「회의 끝내기」
수정   app/(crm)/crm/inbox/SuggestionCard.tsx      — ASK 질문 카드
```

## 화면은

```
인박스  확인 기다림 5건

┌────────────────────────────────────────────────┐
│ WHAT  ○○전자 확장 · 금액                        │
│ 15억 → 40억                                     │
│ 근거 "기존 15억에서 40억으로 증액 요청드립니다"   │
│                         [ 반영 ]  [ 아니오 ]    │
├────────────────────────────────────────────────┤
│ ASK   ○○전자 확장 · 계약 예정일           ← 신설 │
│ 언제 계약 예정인지 회의에서 안 나왔어요.          │
│ 목표 시점이 있나요?                              │
│ 왜  이 딜만 마감일이 비어 있어 예측에서 빠집니다   │
│ [ 2026-__-__ ] [ 저장 ]       [ 모르겠어요 ]    │
├────────────────────────────────────────────────┤
│ ASK   회사 중복 확인                             │

└────────────────────────────────────────────────┘
```

## 되는 것

- **회의 끝나고 버튼 하나** — 정리·5축·빈칸 점검이 한 번에 돈다.
- **AI가 "이건 채워 주세요"라고 묻는다.** 지시하신 그 요구가 여기서 닫힌다.
- 사람이 `ASK`에 답한 값은 **자동으로 확정 처리**되어 이후 AI가 못 덮는다(`verifiedFields` 재사용).
- 급히 적어 생긴 **중복 회사도 질문으로 잡힌다**(`CrmDuplicateCandidate` 재사용).

**확인 방법** — 마감일 없는 딜에 미팅을 붙이고 「회의 끝내기」 → 인박스에 `ASK` 카드가 뜨는지 →
값을 넣고 저장 → **딜 상세에 반영되고 확정 표시가 붙는지.**

# 3차 릴리스 · 시간이 하나의 축이 된다

**약 4일 · 마이그 223 · 선행 1차 · 파일 7개 · 가장 큰 전환점**

## 지금은

**같은 회의인데 어디서 시작했느냐로 캘린더에 뜨고 안 뜬다.**

| 시작한 곳 | 회의노트 | 캘린더 앵커 |
|---|---|---|
| `/meeting-notes` | 생김 | **생김** — `actions.ts:127` |
| `/crm/meetings` | 생김 | **안 생김** — `meeting-publish.ts:428`이 `syncMeetingCalendar`를 안 부름 |

그리고 애초에 **스키마가 막고 있다.**

```sql
-- supabase/migrations/117_meeting_notes.sql:86
check (link_kind in ('daily','weekly','memo','meeting'))
--                    ↑ CRM 도 CI 도 이 축에 올라갈 수 없다
```

캘린더 자체도 **월·주 둘뿐**이고, 보기 상태가 `useState`(`page.tsx:75`)라 새로고침하면 날아간다.

## 이렇게 고친다

### ① 마이그 223 — 축을 넓힌다 (추가 전용)

```sql
check (link_kind in ('daily','weekly','memo','meeting',
                     'crm_meeting','crm_task','ci_schedule'));
add column surface text check (surface in ('member','crm','ci'));  -- 눌렀을 때 갈 곳
```

### ② `lib/calendar/anchor.ts` — 앵커를 한 곳이 판정한다

지금 `meeting-notes/actions.ts:568`에 있는 멱등 upsert 로직을 **여기로 올린다**(복붙 금지).
`createMeetingWithNote`·`updateMeeting`이 이걸 부르면 **위 표의 두 줄이 같아진다.**

- `crm_task`는 **기한이 있을 때만** 앵커를 만든다 — 기한 없는 할 일이 캘린더에 뜨면 소음이다.
- **양방향은 만들지 않는다.** 캘린더에서 지우면 원본이 지워지는 게 아니라
  *"이 일정은 ○○에서 온 것입니다 · 원본 열기"* 라고 말한다.

**기존 일정과 겹칠 때** (지시 원문 "그거와 같은 맥락"):

```
같은 사용자 · 같은 날 · 시작 시각 ±30분 · 제목이나 회사명 겹침
  → 새로 만들지 않고 "이 일정 말인가요?" 를 묻고 고르게 한다
```

**자동 병합하지 않는다** — 틀리면 남의 일정이 엉뚱한 회의에 묶이고 되돌리기 어렵다.

배지를 누르면 **그 표면으로 간다** — 업무는 `/daily`, CRM은 작업대, CI는 `/ci/…`.

## 되는 것

- **어디서 시작했든 캘린더의 같은 자리에 있다.** "캘린더 보면 헷갈린다"가 사라진다.
- **계획과 실행이 한 줄에 보인다** — `예정 → 진행 중 🎙 12분 → 기록됨(38분) → 기록 없음`.
- **일·주·월**이 되고, 새로고침·링크 공유에도 같은 화면.

> **이 차수에서 가장 조심할 것 · 권한**
> `calendar_events` RLS는 계층 플래그가 켜지면 **팀원 것까지 보인다**(마이그 051).
> 그런데 CRM은 워크스페이스 격리다. 그대로 합치면 **"내가 못 보는 딜의 미팅 제목"이 캘린더에 뜬다.**
> → 마이그 223에서 `surface='crm'` 행은 **본인 것만** 보이게 좁힌다. **같은 커밋에서 처리한다.**

**확인 방법** — `/crm`에서 미팅 시작 → `/calendar`에 그 시각에 뜨는지 → 배지 눌러 작업대로 가는지.
그리고 **다른 계정으로 로그인해 그 미팅이 안 보이는지**(권한).

# 4차 릴리스 · 사람에서 되짚고, 홈이 오늘을 말한다

**약 3일 · 마이그 222 · 선행 3차 · 파일 6개**

## 지금은

**참석자가 관계가 아니라 JSON 덩어리다.** FK도 인덱스도 없다.

```prisma
// prisma/schema.prisma — CrmMeeting
attendeesJson Json @default("[]")   // { memberIds: [], personIds: [], externalNames: [] }
```

그래서 **인물 상세에 미팅 패널이 없고**(`PersonDetail.tsx`),
`MeetingPanel`은 `dealId`·`companyId`만 받는다(`MeetingPanel.tsx:47`).
*"누가 참여했고"* 가 출발점인데 **사람에서 되짚는 길이 없다.**

그리고 홈은 `daily_logs`·`weekly_reports`·부서업무만 읽어 **CRM·CI를 아예 모른다.**

- **사람에서 미팅을 되짚는다** — "이 사람과 언제 뭘 이야기했나"가 인물 상세에서 보인다.

## 附 · 미리 정해 둘 것 (현장에서 반드시 부딪힌다)

| 차수 | 상황 | 대응 |
|---|---|---|
| 1차 | **고객 앞에서 노트북을 펼친다** | 첫 화면에 딜 금액·리스크가 떠 있고 **상대가 본다** → 작업대에 **「회의 모드」** 토글. 금액·확률·내부 메모를 가린다. *지시에 없지만 대면을 전제하면 반드시 생긴다* |
| 1차 | **회의실에 네트워크가 없다** | 미팅 생성이 실패하면 「녹음 시작」이 아무 일도 안 한다 → 로컬에 먼저 만들고 연결되면 올린다. 최소한 *"연결이 없어 아직 저장 못 했어요 · 다시 시도"* |
| 1차 | **폰 화면이 잠긴다** | iOS Safari가 녹음기를 죽인다 → `wakeLock` + 잠김 감지 경고. **못 막는 것은 못 막는다고 말한다** |
| 2차 | **이동 중 · 폰 · 5분** | 제안·질문 카드는 한 손으로 처리 가능해야 한다 — 44px 터치 · 스와이프 아님 · 큰 버튼 둘 |
| 2차 | **비용** | 60분 회의 1건 ≈ 5~7만 토큰. 첫 화면에 버튼을 올리면 호출이 는다 → `token-logger`를 `meeting_digest`로 분리 + `CrmAiBudget` 한도. 차면 *"오늘 한도를 다 썼어요"* 라고 **말한다** |
| 3차 | **권한 충돌** | 위 3차 §되는 것 참조 — 같은 커밋에서 RLS를 좁힌다 |

## 附 · 안 하는 것, 그리고 왜

| 안 한다 | 왜 |
|---|---|
| 드래그 대시보드 편집기 | 사람마다 화면이 달라져 "거기 그거"가 안 통한다. 레이어 on/off로 충분 |
| 회의 종료 시 **자동** 정리 | 비용이 새고, 사람이 안 볼 때도 돈이 든다 |
| AI가 채운 값 **자동 반영** | 자동으로 채우면 그 값이 어디서 왔는지 아무도 모른다 |
| 캘린더 ↔ 원본 **양방향 편집** | 캘린더에서 지웠는데 딜이 사라지면 되돌릴 수 없다 |
| 일정 **자동 병합** | 틀리면 남의 일정이 엉뚱한 회의에 묶인다. 묻고 고르게 한다 |
| 새 알림 테이블 | 같은 사실이 두 곳에 생긴다. "지금 상태"를 보는 지금 방식이 맞다 |
| 새 셸 · 새 표 · 새 로딩 부품 | 중복 경보 대상 — 전부 기존 부품을 쓴다 |
