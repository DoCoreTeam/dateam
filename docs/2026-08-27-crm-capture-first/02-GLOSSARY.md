## 00. 왜 필요한가 — 실측

정책 §2-5 (2)에 **"용어는 상수로 고정한다 — 화면에 문자열을 직접 적지 않는다"**가 이미 있다.
그런데 **연동 카드 한 곳에만 적용**돼 있고 나머지는 화면마다 각자 적고 있다.

### 증거 1 · 같은 표를 세 화면이 글자까지 똑같이 복붙

```
app/(member)/meeting-notes/MeetingDetailClient.tsx:32
app/(member)/meeting-notes/MeetingDateView.tsx:7
app/(member)/meeting-notes/MeetingListView.tsx:38

  const STATUS_META: Record<string, { label: string; status: … }> = {
    draft:    { label: '작성중', status: 'planned' },
    final:    { label: '확정',   status: 'done' },
    archived: { label: '보관',   status: 'doing' },
  }        ↑ 세 파일이 완전히 동일. 하나를 고치면 두 곳이 남는다.
           ↑ 게다가 '작성중'은 공백 누락 — 복붙은 오류까지 복제한다
```

### 증거 2 · 라벨 맵이 화면 안에 37개

| 어디에 | 개수 | 판정 |
|---|---|---|
| `lib/**` | 49 | **정상** — 여기가 제자리 |
| `app/**` (화면 안) | **32** (복붙 4벌 제거 후) | **이관 대상** — §2-5 (2) 위반. 두 번째 화면이 쓰는 순간 복붙된다 |

### 증거 3 · 같은 행위를 두 표면이 다른 말로

| 행위 | 쓰이는 말 | 횟수 | 어디서 |
|---|---|---|---|
| 데이터를 없앰 | **삭제** | 16 | `(member)` · `admin` · `(crm)` |
| | ~~지우기~~ | 13 | `(ci)` 6파일 **+ `(crm)` 2파일** — 표면으로 갈린 게 아니라 **그냥 갈려 있다**(가드 실측 정정) |
| 진행 표기 | **삭제 중…** | 4 | 공백 + 말줄임표 |
| | ~~삭제중~~ | 2 | 공백 없음 |
| 새로 만듦 | **새 딜**·**새 회사** | 3 | 명사구 |
| | ~~딜 만들기~~ | 1 | 동사구 |
| | ~~추가~~ | 8 | 무엇을 추가하는지 안 밝힘 |

> **이것이 만드는 결과**: 사용자는 `(ci)`에서 「지우기」를 배우고 `(crm)`에서 「삭제」를 만난다.
> **같은 일인지 확신할 수 없으므로 손이 멈춘다.** 그리고 우리는 이걸 버그로 보지 않아 **영원히 안 고쳐진다.**

### 예외 하나 — 「미팅 기록」

미팅은 **「새 미팅」이 아니라 「미팅 기록」**이다(현재 4곳). 만드는 행위가 아니라
**이미 일어나고 있는 일을 받아적는 행위**라 뜻이 다르다.
**예외는 용어집에 이유와 함께 적는다** — 안 적으면 다음 사람이 "일관성 없다"고 바꾼다.

## 04. 상태 — 색까지 딸려 오는 다섯 칸

상태 라벨은 **반드시 `StatusKey`에 매핑**한다(`lib/tokens/status-colors.ts` · 이미 있음).
그래야 색을 화면이 안 정한다.

| StatusKey | 뜻 | 이 키를 쓰는 상태 라벨 |
|---|---|---|
| `done` | 끝났다 | 정리됨 · 확정 · 올림 완료 · 기록됨 · 반영됨 |
| `doing` | 지금 돌고 있다 | 전사 중 · 올리는 중 · 진행 중 · 보관 |
| `planned` | 예정 · 대기 | 예정 · 작성 중 · 대기 · 확인 기다림 |
| `blocker` | 실패 · 막힘 | 전사 실패 · 올리지 못함 · 기한 지남 |
| `note` | 중립 · 정보 | 기록 없음 · 연결 없음 · 취소됨 |

### 표준 상태 표 — 도메인별

## 05. 시각 — 어느 자리에 어느 포맷인가

## 06. 문장 — 문형을 정한다

`scripts/ui-phrases.mjs`가 이미 **빈 상태·로딩 문구를 판정**한다.
그런데 **표준 문안이 없어서** 각자 쓴다. 문형을 못박는다.

| 자리 | 문형 | 예 |
|---|---|---|
| **빈 상태** `EmptyState` | 제목 `{개체}가 아직 없어요` / 설명 **다음 행동 한 줄** | "딜이 아직 없어요" / "진행 중인 영업 건을 딜로 만들면 단계별로 어디까지 왔는지 보입니다" |
| **오류** `ErrorState` | `{무엇}을 하지 못했습니다.` + 다음 조치. **사과하지 않는다** | "회의노트를 만들지 못했습니다. 잠시 후 다시 시도해 주세요." |
| **삭제 확인** `previewDelete` | `{개체} {N}{조수사}를 삭제할까요?` + **함께 사라지는 것** + **남는 것** | "미팅 1건을 삭제할까요? 참석자 연결·캘린더 일정이 함께 사라지고, 회의노트 원본은 남습니다." |
| **진행** | `{동사} 중…` | "올리는 중 3 / 5" |
| **근거 부족** | `아직 {무엇}이 부족해 말씀드리기 어려워요`. **숫자를 지어내지 않는다** | "비교할 게시물이 3건뿐이라 배수를 내기 어려워요" |
| **섹션 제목** | **명사구.** 대화체 금지 | ✅ 「미팅 기록」 / ❌ ~~「이 날 할 수 있는 것」~~ ~~「지금 회의 중」~~ |

> **마지막 항목이 생긴 이유**: 직전 기획 보고서의 화면 목업에 「이 날 할 수 있는 것」·「지금 회의 중」이라고 썼다.
> **둘 다 시스템에 없는 말**이고, 지시 문장을 그대로 되받아 쓴 것이었다.
> 섹션 제목은 **명사구**이고, 그 자리는 이미 이름이 있다 — **「미팅 기록」**.

## 08. 가드 — 기계가 막는다

**병렬 시스템을 새로 만들지 않는다.** 문구 판정 SSOT는 이미 `scripts/ui-phrases.mjs`이고,
정적 가드는 `lib/ui/*.test.ts` 옆에 붙인다.

| 가드 | 방식 | 무엇을 막나 |
|---|---|---|
| `lib/ui/glossary.test.ts` ① | 즉시 차단 | **금지어**가 JSX 텍스트·문자열에 새로 들어오는 것 |
| `lib/ui/glossary.test.ts` ② | ratchet | `app/**` 안의 **새 라벨맵**. 지금 37개 → **늘면 차단** |
| `lib/ui/duplicate-component.test.ts` | 확장 | **같은 라벨맵이 2곳 이상** 선언 (지금 `STATUS_META` 3벌) |
| `scripts/ui-phrases.mjs` | 확장 | **대화체 섹션 제목** — 동사 종결·의문형 `<h2>`·`<h3>` |

