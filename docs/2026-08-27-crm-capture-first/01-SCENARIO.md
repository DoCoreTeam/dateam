## 00. 먼저 — 1판이 틀렸던 것을 정정한다

1판은 오프라인을 이렇게 썼다 — *"미팅 생성이 실패하면 「녹음 시작」이 아무 일도 안 한다."*
**이건 앱이 떠 있다는 전제였다.** 지시대로 확인해 보니 그 전제부터 틀렸다.

```
$ ls apps/web/public/                                → ax-logo.svg, fonts  (manifest 없음)
$ find . -name "sw.js" -o -name "service-worker*"    → 0건
$ grep "next-pwa\|workbox\|idb\|dexie" package.json  → 0건
```

**PWA도, 서비스 워커도, 로컬 저장 라이브러리도 하나도 없다.**
네트워크가 없으면 `/crm/today`는 **렌더조차 되지 않는다.** "녹음 버튼이 안 눌린다"가 아니라 **화면이 안 뜬다.**

그리고 하나 더 — **녹음 구간 업로드가 실패하면 그 10분이 영원히 사라진다.**
`use-recorder.ts:150`의 `catch`가 상태만 `'failed'`로 바꾸고 **blob을 버린다.** 재시도도 로컬 보관도 없다.

→ **오프라인을 별도 릴리스로 올렸다(2차).** 원래는 1차에 딸린 "주의사항"이었는데,
회의실에서 안 되면 1차 자체가 의미가 없기 때문이다.

> **녹음 파일 올리기** — 폰 녹음기로 따로 녹음한 것을 붙인다 ·
> **안 했어요** — 취소된 회의였다고 표시하고 목록에서 내린다.
>
> **셋째가 중요하다.** "안 한 일"을 지울 방법이 없으면 "기록 없음"이 계속 쌓여서 아무도 안 보게 된다.

# 02. 설계 넷 — 위 시나리오가 요구하는 것

## 설계 1 · 오프라인 3층 — "저장"의 정의를 바꾼다

| 층 | 무엇 | 왜 · 없으면 |
|---|---|---|
| **1층** | 앱이 뜬다 — 서비스 워커 + manifest | 없으면 **화면 자체가 안 뜬다**(F-12). **셸·오늘·이번 주만** 캐시 — 전부 캐시하면 용량과 신선도가 동시에 무너진다 |
| **2층** | 녹음이 안 사라진다 — `lib/offline/blob-store.ts` | 구간을 **IndexedDB에 먼저 쓰고** 업로드. **성공한 것만 지운다.** 지금은 실패하면 버린다(F-13) |
| **3층** | 쓴 것이 안 사라진다 — `lib/offline/outbox.ts` | 미팅 생성·본문 저장·할 일 생성을 큐에. 연결되면 순서대로. **같은 것을 두 번 안 보내게** 요청마다 고유 키 |

> **오프라인에서 안 되는 것도 명시한다.**
> **AI 정리·전사·검색·남의 데이터 조회는 오프라인에서 안 된다.**
> "나중에 됩니다"가 아니라 **화면이 그 자리에서 그렇게 말해야** 사람이 기다리지 않는다.

## 설계 2 · 홈 = 캘린더, 날짜 = 작업대

지시하신 *"다른 배치도 충분히 고려해서"* — 세 안을 비교했다.

| 안 | 모습 | 판정 |
|---|---|---|
| **가 · 캘린더 전면** | 화면 전체가 캘린더. 위젯 없음 | **반려** — 부서업무·주간보고가 갈 곳이 없어진다 |
| **나 · 캘린더 + 오른쪽 레인** | 왼쪽 캘린더(~70%) · 오른쪽 날짜 없는 것 | **채택** — 캘린더가 주인공이면서 **날짜 없는 것이 갈 곳**이 생긴다(G-12). 모바일은 세로 스택 |
| **다 · 위젯 유지 + 순서만 변경** | 지금 배치에서 캘린더만 위로 | **보류** — 가장 안전하지만 "캘린더를 메인으로"에 못 미친다 |

```
채택안 (나)
안녕하세요, 도현님        [일│주│월]  ⚙
┌ 캘린더 ─────────────┐┌ 날짜 없음 ──┐
│ 월  화  수  목  금   ││ 기한 없는    │
│                     ││  할 일 2     │
│     업무 CRM  CI     ││ 다음 행동    │
│                     ││  없는 딜 1   │
│  27일 클릭           ││ ──────────   │
│    ↓                ││ 부서 업무    │
│  하루 작업대          ││              │
└─────────────────────┘└──────────────┘
┌ 오늘 업무 ┐┌ 메모 ┐┌ 주간보고 ┐
└───────────┘└──────┘└──────────┘
```

## 설계 3 · CRM 메뉴 12 → 5

**화면을 없애는 게 아니라 탭으로 내린다** — 20개 화면은 그대로 산다.

```
지금 · 12개                   묶은 뒤 · 5개
──────────────────           ──────────────────
☀ 오늘                        ☀ 오늘  (3)      ← 인박스 흡수
📥 인박스 (3)                 🤝 딜
🤝 딜                              └ 파이프라인 · 견적
📄 견적                       🏢 거래처
🏢 회사                            └ 회사 · 인물
👥 인물                       🎙 기록
[기록] 미팅 · 할 일                └ 미팅 · 할 일 · 변경 이력
[보기] 리포트 · 변경 이력       📊 리포트
[설정] 영업단계 · 멤버 · 설정
                             영업 단계·멤버·설정 → 계정 메뉴(우상단)
```

| 묶음 | 왜 같이 묶나 |
|---|---|
| **오늘** ← 인박스 | 둘 다 "지금 봐야 할 것"이다. 인박스를 따로 두면 **안 열어 보고 제안이 만료된다** — 지금 뱃지를 다는 이유가 그것이다 |
| **딜** ← 견적 | 견적은 딜 금액의 **근거 문서**다. 코드 주석도 그렇게 써 놓고 **메뉴만 따로** 뒀다 |
| **거래처** ← 회사·인물 | 같은 것의 두 면. 영업은 "○○전자의 배수현"을 찾지 "인물 목록"을 찾지 않는다 |
| **기록** ← 미팅·할 일·변경 이력 | 전부 "무슨 일이 있었나"다. 변경 이력이 「보기」에 따로 있을 이유가 없다 |
| **설정 3개 → 계정 메뉴** | 처음 한 번 정하고 가끔 손보는 것. 매일 쓰는 것 옆에 두면 매일 쓰는 것이 안 보인다 |

## 설계 4 · 화면 전환 규칙

| 동작 | 방식 | 이유 |
|---|---|---|
| 날짜 클릭 | **패널** `?day=` | 돌아올 곳이 바로 캘린더다 |
| 회의 기록 시작 | **라우트** `/crm/meetings/{id}` | 회의 내내 머무는 화면. 주소가 있어야 새로고침·복귀가 된다 |
| 목록 → 상세 | **라우트** | 공유·북마크·뒤로가기가 필요하다 |
| 상세 안의 탭 | **같은 화면** `?tab=` | 견적·미팅은 딜을 보는 여러 각도일 뿐 |
| 인박스 제안 처리 | **제자리** | 다섯 개 처리에 다섯 번 이동하면 아무도 안 한다 |
| 일정·할 일 만들기 | **모달** | 하던 일로 바로 돌아와야 한다 |

> **규칙 한 줄**: **"머무는 곳"만 라우트다.** 회의 작업대와 상세 화면 둘뿐, 나머지는 패널·탭·모달.
> **단, 패널도 URL을 갖는다**(`?day=`·`?meeting=`) — 안 그러면 "화면 전환 없음"이
> **링크 공유와 뒤로가기를 죽인다**(G-15).

# 03. 말씀 안 하신 것 중 반드시 정해야 하는 것 7개

**G-9. 로컬 우선 저장의 진짜 위험 — 다른 기기에서는 안 보인다.**
폰으로 녹음하고 노트북으로 열면 **폰 IndexedDB에 있는 것은 안 보인다.** 사용자는 "녹음이 날아갔다"고 생각한다.
→ 서버에 **"아직 안 올라온 것이 있다"는 표시만 미리 남긴다.** 다른 기기에서 열면
*"이 회의의 녹음 3구간이 다른 기기에 있습니다"*.

**G-10. 브라우저가 로컬 저장분을 조용히 지울 수 있다.**
60분 녹음 ≈ 30~60MB. IndexedDB는 공간이 부족하면 **브라우저가 경고 없이 지운다**(eviction).
로컬 우선 저장은 **이걸 막지 않으면 오히려 더 위험하다.**
→ `navigator.storage.persist()`로 영구 보관 요청, 거부되면 **말한다.** 용량 부족은 녹음 시작 전에 알린다.

**G-11. 고객 회의 음성이 기기에 남는다.**
노트북을 분실하면 **고객사 회의 녹음이 통째로 나간다.** 로컬 우선 저장이 만드는 새 위험이다.
→ **업로드 성공 즉시 로컬 원본 삭제.** 못 올린 것도 **보관 기한(예: 7일)**, 기한 전 알림, 지우기 전 한 번 더 확인.

**G-12. 캘린더가 메인이 되면 "날짜 없는 것"이 갈 곳을 잃는다.**
기한 없는 할 일 · 다음 행동 안 정한 딜 · 확인 안 한 메모 — **지금 홈 위젯이 보여 주던 것들**이다.
→ 캘린더 옆 **「날짜 없음」 레인**(설계 2 채택안). 여기서 날짜를 끌어다 놓으면 일정이 된다.

**G-13. 같은 회의에 두 명이 각자 녹음을 시작한다.**
팀 2명이 각자 누르면 **미팅이 2개 생긴다.** 인박스에 같은 제안이 두 벌 뜬다.
→ **같은 캘린더 일정에 붙는 미팅은 하나.** 두 번째 사람에게는
*"김대리님이 이미 이 회의를 기록 중입니다 · [같이 기록] [따로 만들기]"*.

**G-14. 오프라인에서 만든 것끼리 충돌한다.**
폰과 노트북에서 각각 오프라인으로 만든 미팅이 같은 회의라면? 연결되면 둘 다 올라간다.
→ 큐의 각 요청에 **고유 키**, 서버가 **±30분 규칙**으로 후보를 찾아 `ASK`로 묻는다. **자동 병합하지 않는다.**

**G-15. "화면 전환 없음"이 링크 공유와 뒤로가기를 죽인다.**
모든 것을 패널로 만들면 **"이 날짜 좀 봐 주세요"를 보낼 방법이 없어진다.**
→ **패널도 URL을 갖는다.** 이 저장소가 이미 쓰는 규약(`useListQuery`)과 같다.
