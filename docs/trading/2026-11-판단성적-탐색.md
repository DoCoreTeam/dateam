# 판단 성적 탐색 v0.11.108

판정: 지금의 1분 진입 조건 판단은 손절 목표 보유 시간 시간대를 어떻게 바꿔도 비용을 넘기지 못한다, 이 판단으로는 신호를 내지 않는다

- 조건: 2026-09-28 ~ 2026-11-09 규칙 판단 1,923건, 비용(왕복 미끄러짐 2틱씩, 수수료 편도 0.00185%) 포함, 1계약
- 기능 판정: 성적 관문(v0.11.108)이 이 성적으로 신호를 막는다, 운영 판정 Profit Factor 0.90 기준 1.25 미달
- 성과 판정: 답을 주는 것은 확인 구간 성적이다, 탐색 구간에서 고른 조합이 확인 구간에서도 건당 R 0 초과이고 Profit Factor 1.25 이상이며 결판 500건 이상(성적 관문 기준)이면 그 조합을 쓸 수 있다, 이번 64개 조합 중 그런 조합은 0개
- 다음 행동: 1분 방향 맞히기를 다듬지 않는다, 판단의 재료(진입 조건과 지표)를 바꾼 새 가설을 같은 스크립트로 먼저 재고 확인 구간을 넘을 때만 화면에 올린다

## 왜 그런가

- 방향에 정보가 없다
  - 2026-11-05 기준 판단 3,390건, 판단 뒤 1분 5분 15분에 그 방향으로 움직인 비율 48.4% 48.2% 50.3%, 통계적으로 동전과 구별 안 됨
  - 15분 뒤 평균 움직임 -0.10포인트, 왕복 비용 약 0.12포인트
  - 판단과 반대로 들어가도 Profit Factor 0.85, 맞히는 쪽도 틀리는 쪽도 아니고 비용만 빠진다
- AI 판단이 규칙을 따라 말한다
  - 같은 봉 1,757건 중 1,750건이 규칙 판단과 같은 방향(99.6%), 그래서 이 탐색은 규칙 판단만 센다
- 성적이 한때 플러스로 보인 것은 채점 결함이었다
  - 진입가가 이미 손절선 너머인데 손절가에 판 것으로 세어 손절 287건이 이익으로 잡혔다(+14,593,723원)
  - v0.11.108 에서 고침, 손절인데 이익인 건수 0

## 읽는 법

- 시간대별 표에서 탐색 구간에 좋았던 10~11시가 확인 구간에서 가장 나빴고(건당 R 0.056 에서 -0.223), 09시는 거꾸로였다, 시간대 차이는 우연의 크기 안에 있다
- 격자 상위 다섯은 탐색 구간에서도 전부 마이너스였고 확인 구간에서도 전부 마이너스였다, 손절을 넓히고 보유를 줄일수록 덜 잃을 뿐이다
- 전체 구간에서 플러스인 조합 하나는 탐색과 확인 둘 다 플러스가 아니었다, 고르면 과적합이다

## 다시 돌리는 법

- 자료 셋을 psql 로 뽑는다 (접속값은 apps/web/.env.local 의 DIRECT_URL)
  - judgments.json: `select json_agg(j) from (select id, contract_code, bar_close_at, judge, raw_score from trading_judgments where status='completed' and raw_score is not null order by bar_close_at) j`
  - bars.json: `select json_agg(b) from (select contract_code, bar_start_at, open, high, low, close, volume from trading_bars where tf='1m' order by contract_code, bar_start_at) b`
  - settings.json: `select json_object_agg(key, value) from (select distinct on (key) key, value from trading_settings order by key, effective_trade_date desc, version desc) s`
- apps/web 에서 `node --experimental-strip-types scripts/trading-sweep.ts judgments.json bars.json settings.json`
- 채점은 화면과 백테스트가 쓰는 lib/trading/judge/score.ts 그대로다, 스크립트에서 셈을 고치지 않는다
