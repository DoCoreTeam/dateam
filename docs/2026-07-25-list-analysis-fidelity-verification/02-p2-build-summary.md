# P2 구현 요약 — 입력유형 자동분기 · 충실도 신호 · 골든셋

## 구현 (결정론 우선 — 추가 AI콜 0)
- **입력유형 자동 모드분기**: `classifyDensity(source)`(retention.ts) → augment 프롬프트 강조 전환.
  - dense(표·ID·수치 다수, 정본): "부풀리지 말고 검증·갭·리스크·미결 중심 보강".
  - sparse(짧은 목록): "생략된 실행 상세 적극 펼치기".
  - refineGroupItem이 `group.bodyRaw` 밀도로 자동 선택.
- **충실도 신호(결정론 프록시)**: `computeAddedNumbers(source, result)` → 결과에 새로 등장한 수치(원문 근거 없음)를
  카드에 "🔬 AI가 더한 수치 N개(검토 권장): …"로 표시. **정확히 어떤 값을 검증할지 짚어준다.**
- **골든셋 회귀평가**: `analyze-golden.test.ts` — 대표 정본/목록의 밀도분류·엔티티추출·보존율·추가수치 계약 고정.

## 왜 per-item LLM-judge를 안 썼나 (TRADEOFF)
Gemini 429 상시 소진 + 항목마다 추가 호출 = 비용·실패면 증가. 결정론 프록시가 오히려
"검증할 값을 특정"해줘 실용적. 완전 LLM 충실도 판정은 필요 시 별도 도입.

## 검증
- 단위/골든 테스트 추가(밀도·추가수치·골든 6), 전체 1335/1335 통과. tsc/design 초록.
- 실브라우저: 결제 정본 → "AI가 더한 수치 4개(…검토 권장): 1시간, 24시간, 7일" 칩 실표시(섹션번호 오검출은 METRIC_RE 정정으로 제거).
