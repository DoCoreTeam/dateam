# P0+P1 상세 설계 — 목록 심층분석 충실도·비교 (착수 대기, 구현 보류)

> 사용자 선택: **P0+P1** (원문↔결과 diff + 증강 모드 기본화 + 보존율 지표 + 생략 경고 + 품질 배지).
> 상태: 설계 확정. **승인 시 구현 착수** — 현재는 코드 미변경.

---

## 완료 기준 (승인 후 이 체크박스로 GATE)

### P0 — 비교 + 증강 (양 감소·비교불가 해소)
- [ ] **원문↔결과 비교 뷰**: 결과 카드에 "원문 보기/비교" 토글. `body_raw`(이미 저장됨)를 결과와 나란히/토글. 추가=초록·삭제/누락=빨강 하이라이트(라인 단위 diff).
- [ ] **증강 모드 기본화**: 심화 결과 = `원문 verbatim 보존` + `── 분석/보강 ──` 섹션. 원문을 재서술·대체하지 않는다. → 양이 원문 이하로 절대 안 내려감.
  - refine 프롬프트에 "원문을 다시 쓰지 말고 그대로 둔 뒤, 그 아래에 실행기준·판단축·수치를 보강만 하라" 명시.
  - 렌더는 `원문 블록(회색) + 보강 블록`. 저장은 result_text에 둘 다 포함(export 일관).
- [ ] 회귀 0: 무지시/희소 목록 입력은 기존 확장 동작 유지(증강 모드는 고밀도 정본에서 특히 이득).

### P1 — 보존율 + 생략 경고 + 품질 배지 (생략 여부 자동 신호)
- [ ] **엔티티 추출(결정론)**: 원문 그룹에서 ID(FR/NFR/D/V-\d+), 숫자+단위, 대문자 약어/고유명사, 표 셀 헤더를 정규식으로 추출 → `lib/ai-chat/analyze/retention.ts`(신규, 순수함수, 단위테스트).
- [ ] **보존율 계산**: 추출 엔티티가 result_text에 존재하는 비율. 항목별 `{idPreserved, numPreserved, missing[]}`.
- [ ] **생략 경고 + 보수 재생성 1회**: 누락 엔티티 있으면 카드에 "누락: FR-103·30일·PASS" 경고 + "누락분 반영" 버튼(해당 항목만 보수 프롬프트로 재심화).
- [ ] **품질 배지**: 카드 우상단에 "ID 12/12 · 수치 8/8 · +N 보강" 배지(status-colors 토큰 재사용). 미달=경고색.
- [ ] 무손실 배지 문구 정정: "그룹핑 라인 무손실" ≠ "심화 무손실"임을 툴팁으로 구분.

## 아키텍처 (SSOT·재사용 우선)

| 관심사 | 위치 | 신규/재사용 |
|---|---|---|
| 엔티티 추출·보존율 | `lib/ai-chat/analyze/retention.ts` | **신규**(순수·테스트) |
| 라인 diff | `lib/ai-chat/analyze/text-diff.ts` 또는 기존 diff 유틸 재사용 | 조사 후 결정 |
| 증강 프롬프트 | `lib/ai-chat/grouping/refine-group.ts` `buildAugmentPrompt`(신규) | refine SSOT 확장 |
| 원문 노출 | `AnalysisResultItem`에 `bodyRaw` prop 추가(세션 로드에 body_raw 포함) | 배선 |
| 배지·경고 | `AnalysisResultItem` + `retention` 결과 | UI |
| 보수 재생성 | 기존 `retryItem`/보수 패스 재사용 | 재사용 |

- **DB 변경 최소**: `body_raw`는 이미 `ai_analysis_items`에 있음(저장 O). 보존율은 표시 시점 계산(저장 불필요) 또는 캐시 컬럼 1개(선택). → **마이그레이션 없이 시작 가능**할 가능성 높음(조사 확정).

## 검증 (구현 중)
- 단위: retention.ts(ID/수치/약어 추출·보존율·누락), 증강 프롬프트 스냅샷.
- 실브라우저(직접): 고밀도 정본 1건 → 증강 모드 결과가 원문 이상 분량 + diff에서 원문 100% 유지 + 보존율 배지 100% 확인.
- 대조: 현행 vs 증강 모드 보존율·문자수 수치 비교(양·보존 개선 실측).

## 범위 밖 (P2 — 이번 아님)
- 입력유형 자동 모드분기, 충실도(환각) LLM-judge, 골든셋 회귀평가 → 별도 승인 시.

## 리스크
- 라인 diff가 표(마크다운) 재배치에서 노이즈 → 엔티티 단위 diff 병행으로 완화.
- 증강 모드로 결과가 길어짐 → 접기/펼치기 기본 접힘 유지.
