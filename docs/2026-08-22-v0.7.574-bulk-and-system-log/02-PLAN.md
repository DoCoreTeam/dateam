# 기획 — 일괄작업 · 실패의 말 · 시스템 관측

> 2026-08-22 · 근거는 `01-FINDINGS.md` · **구현 없음. 승인 대기.**

## 이 기획을 관통하는 판단 하나

발견 14건을 늘어놓으면 서로 다른 일처럼 보이지만, **셋 다 같은 모양**이다.

> **자리는 이미 있는데 아무것도 안 들어간다.**

- `ai_token_logs.success/error_message` — 컬럼이 마이그 011부터 있는데 `false` 를 넣는 코드가 0곳
- `crm_ai_run.status='FAILED'` — 잘 쌓이는데 읽는 화면이 0곳
- `선택 삭제` 패턴 — 호스트에 이미 있는데 CRM 이 안 씀
- `ListPager` 의 `page` patch — 주는데 화면이 버림
- `checkThreshold` 의 알림 — 중복방지 표시만 남기고 안 보냄

그래서 이 기획의 원칙은 **"이미 있는 것을 먼저 잇는다"** 이다.
1·2차는 **새 테이블 0개**로 끝난다 — 자리가 이미 있으니 켜기만 하면 된다.

**단 한 곳에서 이 원칙을 접는다.** 3차의 `system_events` 다.
2차 조사에서 실패 출처 **8개 중 5개는 테이블 자체가 없다**는 것이 드러났고(전부 `console.error` · 186곳),
**없는 것을 UNION 할 수는 없기 때문이다.** 판단을 바꾼 것이지 잊은 것이 아니며,
그 이유와 기존 테이블과의 경계를 §3-0 에 적어 뒀다.

그 밖에는 그대로다 — **새 종 0개 · 새 사유 분류 0개 · 새 목록 부품 0개.**

## 1차 · 프로덕션에서 지금 깨져 있는 것 (서버, 소량)

> 이 넷은 서로 얽혀 있어 **한 커밋**으로 간다. 화면 변경 없음.

### 1-1. `maxDuration` 선언 (B-2)

```ts
// app/api/crm/companies/enrich/route.ts
export const maxDuration = 300   // 형제 라우트(analyze/stream · cron/analyze-drain · leads/parse)와 같은 값
```

`[id]/enrich` 는 1곳이므로 `60`.

**왜 지금**: 로컬에는 함수 시간 상한이 없어 이 결함은 개발 중 절대 안 보인다. 선언 한 줄이 프로덕션 절단을 막는다.

### 1-2. AI 한도(429)를 **중단 조건으로 승격** (B-3)

`CrmErrorCode` 에 `PROVIDER_QUOTA` 추가(HTTP **429**, `BUDGET_BLOCKED` 옆자리).

```ts
// lib/crm/ai/runner.ts — 지금은 전부 VALIDATION_FAILED(400)
const c = classifyProviderError(lastError)
throw new CrmError(
  c.availability ? 'PROVIDER_QUOTA' : 'VALIDATION_FAILED',   // limited|unavailable → 429
  c.message,
)
```

```ts
// lib/crm/services/enrich-web.ts — 중단 조건 확장
const STOP_CODES = ['BUDGET_BLOCKED', 'PROVIDER_QUOTA'] as const
if (e instanceof CrmError && STOP_CODES.includes(e.code)) { stopped = e; break }
```

**효과**: 최대 40회의 헛호출 → **1회**. 동일 문구 20줄 → **1줄**.
분류는 `classifyProviderError`(기존 SSOT)를 그대로 쓴다 — 새 판정 규칙을 만들지 않는다.

### 1-3. 중단되면 **남은 회사를 명시한다** (B-5)

응답에 필드 하나 **추가**(M-4 추가 전용 — 기존 필드 무변경):

```ts
interface EnrichCompaniesResult {
  results; enriched; applied; suggested; failed;
  /** 중단돼서 **시작조차 못 한** 회사들. 지금은 조용히 사라진다 */
  notStarted: { companyId: string; reason: string }[]   // ← 신설
}
```

화면 문구: `"AI 한도 초과로 17곳은 시작하지 못했어요. 한도가 풀린 뒤 다시 눌러 주세요."`

### 1-4. 실패 줄에 **회사 이름** (B-4)

서버 변경 불필요 — 화면이 이미 `rows` 를 들고 있다. `companyId → name` 을 화면에서 해결한다.

**검증(E-4)**: 429 상태에서 20곳 선택 → ① 헛호출 1회인지 ② 문구 1줄인지 ③ 남은 19곳이 명시되는지 ④ HTTP 429 인지.

## 2차 · 사용자가 화면에서 겪는 것

### 2-1. 목록 표준의 "기본값 되돌리기" 구멍 (A-1) — **SSOT 한 곳**

세 안을 놓고 골랐다.

| 안 | 내용 | 판정 |
|---|---|---|
| (a) 기본값도 URL 에 항상 쓴다 | `listQueryToParams` 에서 생략 제거 | **반려** — 설계 의도 역행. 주소가 길어지고 **기존 공유 링크의 뜻이 바뀐다** |
| (b) `set()` 이 URL 무변화를 감지해 리비전을 올린다 | `useListQuery` 가 `queryKey` 를 함께 낸다 | **채택** |
| (c) `more` 목록이 화면에서 개별 대응 | 화면마다 size 변경 시 누적 리셋 | **반려** — 40여 화면에 같은 코드. §재사용 정책 위반 |

**채택안 (b) 의 모양**

```ts
const { query, set, queryKey } = useListQuery(defaults)
//                  ^^^^^^^^ "지금 조건" 을 담은 문자열. 같은 조건을 다시 확정하면 값이 바뀐다.

const load = useCallback(async (…) => { … }, [queryKey])   // 화면은 이것 하나만 의존한다
```

- `set()` 이 만든 주소가 현재와 **같으면** 내부 리비전을 올려 `queryKey` 를 바꾼다 → 재조회가 일어난다.
- 다르면 지금처럼 `router.replace` — 기존 동작 **무변경**.
- 화면 API 는 **추가 전용**(`queryKey` 가 늘어날 뿐 `query`·`set` 은 그대로) → 40여 화면을 한꺼번에 안 고쳐도 된다.

**가드**: `lib/ui/list-standard.test.ts` 에 규칙 추가 — `useListQuery` 를 쓰면서 로드 콜백 deps 에
`query.size`/`query.q` 같은 **개별 필드만** 나열한 화면을 ratchet 으로 센다(기존 화면은 baseline, 새 화면은 차단).
**가드는 만든 뒤 일부러 깨서 실패를 확인한다**(v0.7.438 전례).

## 3차 · 시스템 로그 — 메뉴 하나에 모든 로그 (사용자 신규 요구 · **확장됨**)

> 1차 지시: "관리자쪽에 이런 로그들이 표현되는 곳이 필요할것 같은데 … AI 한도가 없으면 그런걸 체크 할 수 있을텐데 알림도 표시 되야 하고"
> **2차 지시**: "관리자페이지에 **시스템로그 메뉴 하나** 두고 거기에 **모든 로그**를 남기자 …
> 로그방식은 시스템 로그보다는 **어떤 관리자가 봐도 명확한 자연어 수준**으로 …
> 그리고 **해결 방법까지 AI 써서** 알려주자"

**➡ 상세 설계는 [`03-SYSTEM-LOG.md`](./03-SYSTEM-LOG.md) 로 분리했다.** 여기에는 결정과 그 이유만 남긴다.

### 3-0. 초판에서 **뒤집은 판단** — 새 테이블을 만든다

초판은 "새 테이블 금지"였다. AI 실패에 한정하면 맞았다(`ai_token_logs.success` 라는 빈 자리가 있었으므로).
그런데 지시가 **"모든 로그"** 로 넓어지면서 전제가 깨졌다 — 2차 조사 결과:

> 실패 출처 **8개 중 5개는 테이블 자체가 없다**(전부 `console.error`, 186곳). **UNION 할 대상이 없다.**

없는 것을 UNION 할 수는 없다. 그래서 **싱크 하나(`system_events`)를 만든다.**
단 기존 테이블을 **대체하지 않는다** — 경계 판정 기준은 한 줄이다:

| | 지우면 |
|---|---|
| `ai_token_logs`·`crm_ai_run`·`ci_jobs` (도메인 진실) | **시스템이 망가진다** → 그대로 둔다 |
| `system_events` (사람이 읽는 사건) | **아무것도 안 망가진다** → 90일 보존 후 삭제 |

숫자(정산·집계) 층과 문장(무슨 일이 있었나) 층이라 **중복이 아니라 역할이 다르다.**

### 3-1. 자연어는 **두 층** — 그리고 ①은 AI 없이 완전하다

이 설계를 지배하는 판단 하나:

> **시스템 로그 화면이 AI 에 의존하면, AI 가 죽었을 때 그 사실을 볼 수 없다.**

이 화면을 원하신 이유가 정확히 "AI 한도가 없으면 그런 걸 체크"다. 그 화면의 문장을 AI 가 만들면
한도가 소진된 바로 그 순간 화면이 통째로 빈다. **관측 도구가 관측 대상과 함께 죽는다.**

| 층 | 무엇 | AI | 없으면 |
|---|---|---|---|
| **① 사실 문장** | 무엇이 안 됐나 · 왜 · 누가 · 언제 · 얼마나 · 어디서 | **안 씀**(`lib/system-log/narrate.ts` 순수함수) | — 항상 있다 |
| **② 해결 방법** | 원인 · 확인할 것 · 조치(위험도·되돌림 여부) | 씀 — **요청형 · 지문당 1회** | ①은 그대로 읽힌다 |

```
지금:  [crm/api] PrismaClientKnownRequestError … `public.crm_company` does not exist (P2021)
뒤 :  ⛔ 회사 목록을 불러오지 못했습니다
        데이터베이스에 'crm_company' 표가 없습니다 — 마이그레이션이 아직 적용되지 않은 것으로 보입니다.
        김도현 외 3명 · 오늘 21:34부터 12번 · /crm/companies
```

**AI 해결책의 안전장치 넷**(상세 §4)
- **지문(fingerprint) 단위 1회** — 같은 오류 500건에 500번 부르지 않는다
- **요청형** — 화면 열 때 자동 호출 금지(로그 100줄 = AI 100회가 되는 자기모순)
- **한도(quota) 사유엔 AI 를 안 부른다** — 또 실패한다. 우리가 미리 쓴 **정적 플레이북**으로 답한다
- **자동 실행 없음**(§5-3) — 조치는 읽을거리다. 근거 없으면 "모르겠다"고 말하게 한다

### 3-2. 쓰는 곳은 **길목 6개** — `console.error` 186곳을 고치지 않는다

CRM API 예외(`lib/crm/api/handler.ts` — **이미 단일 통로**) · 호스트 AI(`gemini-call.ts`) ·
CRM AI(`runner.ts recordFailure`) · CI 잡(`ci/jobs/queue.ts`) · 크론·잡(`withJobRun()` 신설) ·
클라이언트(`global-error.tsx` 신설 — 지금 `error.tsx` 가 **1개뿐**).

호스트 API 201개는 공용 핸들러가 없어 이관 자체가 별건이다 → **4차.**
위 6곳으로 AI·CRM·잡·크론·클라이언트가 이미 덮인다.

**쓰기 규칙 셋**: fire-and-forget(원래 요청을 막지 않는다) · 같은 지문 분당 상한(로그가 장애를 키우면 안 된다) · 키·토큰 마스킹 + 가드.

### 3-3. 마이그레이션 — **계획 변경**

초판의 `ai_token_logs.failure_reason` 추가는 **철회**한다. 사유 필터는 `system_events.reason` 이 맡는다.
`ai_token_logs` 는 `success=false` 기록만 켜서 사용량 대시보드의 **성공률**을 맞춘다(스키마 변경 불필요).

→ **마이그 215 = `system_events` + `system_event_remedies`** 하나. 번호는 파일 생성으로 즉시 선점(M-3).

### 3-4. 화면 — `/admin/system-log` 메뉴 **하나**

`app/admin/layout.tsx:41-49` 의 `API · 시스템` 그룹(이미 있음)에 한 줄.
목록 표준(§2-6) 그대로 — `ListToolbar`+`ListSurface`+`ListPager`+`useListQuery`.
맨 위 **"지금 막혀 있는 것"** 상태 카드(AI 안 씀) → 지문 단위로 접힌 목록 → 펼치면 사실 문장 + [해결 방법 보기] + 원문 + [처리함].

**"처리함"은 사건이 아니라 상태다** — 다시 발생하면 되살아난다(`AttentionBell` 철학).

### 3-5. Vercel 로그 — 링크만 둔다

같은 화면 우측 상단에 **"Vercel 로그 열기"** 외부 링크 버튼 하나. 토큰 불필요, 즉시 유용.

**지금 API 로 끌어오지 않는 이유 셋** (판단이지 게으름이 아니다):

1. `apps/web/.env.example`(v0.7.572 신설)에 `VERCEL_*` 이 **없다** — 토큰이 아직 없다.
2. **실측 함정**: Vercel 로그 API 는 `page=` 커서가 안 먹어 **같은 50건이 반복**된다(v0.7.572 작업 중 확인). `endDate` 커서로 훑어야 하는데, 그걸 제대로 만들려면 그 자체가 별건이다.
3. 그리고 **지금 필요한 신호는 전부 우리 DB 에 이미 있다.** Vercel 로그가 답하는 것은 그 아래 인프라 계층(504·콜드스타트·빌드)이라 성격이 다르다.

→ 인프라 계층 사고가 실제로 문제가 되면 4차에서 Log Drain 으로 붙인다. **그때 위 함정을 문서에 남긴 채로 시작한다.**

### 3-6. 알림 — **세 번째 종을 만들지 않는다**

지금 종이 둘이고, 철학이 다르다.

| 부품 | 붙은 곳 | 철학 |
|---|---|---|
| `NotificationBell` (CI) | `(ci)` 만 | 사건을 **쌓는다**(읽음/안읽음) |
| `AttentionBell` (CRM) | `(crm)` 만 | 지금 **상태**를 본다(해결되면 사라짐) |

**AI 한도 소진은 "상태"다** — 한도가 리셋되면 저절로 풀린다. 그러니 `AttentionBell` 쪽 철학이 맞다.

**그런데 이번에 종을 건드리지 않는다.** 이유:

- 종 2벌 병존은 CI·CRM 양쪽의 설계 결정이라 **이 기획 단독으로 정하면 안 된다**(M-8: 만든 사람이 유일한 검토자가 될 수 없다).
- 지금 급한 것은 **어드민이 볼 자리**이고, 그건 3-2 의 상태 카드로 해결된다.

**이번에 하는 것**

1. `/admin/system-log` 상단 상태 카드 (3-2)
2. `/admin/ai-usage` 배너에 **한도 실패 상태**를 추가 — 지금 배너는 **월 토큰 총량 임계치**만 본다. 사용자가 겪는 429(프로바이더 한도)와는 **다른 신호**인데 화면에 그 구분이 없다.
3. **죽은 알림 코드 정리** — `lib/token-logger.ts` 의 `ai_token_alert_sent_month` 는 "보냈다" 표시만 남기고 아무 데도 안 보낸다. 3-2 의 상태 카드로 대체하고 **그 플래그를 걷어낸다.**

**다음으로 미루는 것(별도 기획)**: 종 통합 — `AttentionBell` 을 `AppShell` 공통으로 올리고 `attention.ts` 에 `system` kind 를 추가하는 안. **CI/CRM 소유 세션과 합의가 먼저다.**

### 완료의 뜻 (E-1~E-6)

- 회사 목록에서 `더 보기` 2회 → "20개씩" → **행이 20으로 준다**
- 2건 선택 → **선택 삭제** → 확인창이 함께 사라지는 것을 보여 준다 → 목록에서 빠진다 → 휴지통에서 **되돌린다**
- 20곳 AI 보강 → **진행이 한 줄씩 나타난다** → 한도면 **1줄로 말하고 멈춘다** → 남은 곳을 명시한다
- 일부러 실패를 낸다 → `/admin/system-log` 에 **자연어 한 줄**로 뜬다 → 5번 내면 **5줄이 아니라 1줄 + "5번"**
- [해결 방법 보기] → 진단이 뜬다 → 같은 지문을 다시 눌러도 **AI 호출이 안 나간다**(네트워크 탭)
- **한도(429) 사유는 AI 를 안 부르고 플레이북이 뜬다** — 관측이 관측 대상과 함께 죽지 않는다
- 로그에 **키·토큰이 안 남는다** · 관리자 아닌 계정은 `/admin/system-log` 가 **막힌다**
- 로그 0건일 때 **"아무 문제 없습니다"** 라고 말한다(빈 화면 아님)
- 콘솔 오류 0
- **넣은 테스트 데이터는 되돌린다**(운영 데이터)
