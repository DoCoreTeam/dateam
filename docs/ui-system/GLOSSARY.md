# GLOSSARY — newAX 용어집 (말의 SSOT)

> `INVENTORY.md` 는 **무엇으로 그리는가**(부품)를 정한다.
> 이 문서는 **무엇이라고 부르는가**(말)를 정한다. 둘이 짝이어야 같은 제품이 된다.

**코드 상수(2층)**: `apps/web/lib/terms/` — 화면은 `@/lib/terms` 하나만 import 한다.
**가드(3층)**: `apps/web/lib/ui/glossary.test.ts` — 새 위반을 기계가 막는다.

---

## 0. 새 화면을 만들기 전에

1. **여기서 말을 찾는다.** 있으면 그 상수를 쓴다.
2. **없으면 여기에 먼저 추가**하고 `lib/terms/` 에 상수를 만든 뒤 화면에서 쓴다.
3. **화면에 한글 문자열을 직접 적지 않는다.** 두 번째 화면이 쓰는 순간 복붙된다.

> 이 규칙이 없어서 생긴 일(실측 v0.7.597):
> 같은 상태 표가 회의노트 화면 **3벌**, GPU 과금 표가 **2벌** 복붙돼 있었고,
> 회의노트 3벌은 **오탈자(`작성중` — 공백 누락)까지 똑같이** 복제돼 있었다.

*예외는 이유와 함께 적는다 — 안 적으면 다음 사람이 "일관성 없다"며 바꾼다.*

## 2-2. 매출 인식 장부 — `lib/terms/ledger.ts`

> **왜 따로 두나**: 장부는 화면 하나가 아니라 **딜 상세·리포트·견적·정산**이 함께 읽는다.
> 화면마다 「수주 매출」·「총 사업비」·「계약금액」으로 갈리면 사용자는 같은 숫자를 다른 것으로 읽는다.

### 금액의 이름

| 라벨 | 상수 | 무엇인가 |
|---|---|---|
| 수주 매출 | `LEDGER.booked` | **전체 사업비.** 영업 실적·목표의 기준이 되는 큰 숫자 |
| 현물 제외 | `LEDGER.exInKind` | 수주 매출 − 현물. **저장하지 않는다 — 파생이다** |
| 회계 수익 인식 | `LEDGER.accountingRevenue` | 국비 + 지방비. 회계가 매출로 인식하는 금액 |
| 현금 유입 | `LEDGER.cashInflow` | 현물이 아닌 재원의 합 |
| 공급가액 | `LEDGER.net` | 부가세를 뺀 금액 — ~~부가세 별도금액~~ 금지 |
| 부가세 / 합계 | `LEDGER.tax` / `LEDGER.gross` | |

### 수주 매출의 출처 — `BOOKED_FROM_LABEL`

`계약 금액` > `견적 금액` > `예산 금액` 중 **가장 확실한 것**을 쓰고, 그 사실을 화면이 밝힌다.
셋 다 없으면 이관 중인 옛 칸을 `금액`이라는 이름으로 쓴다 — 사용자에게 「옛 칸」이라고 말하지 않는다.
넷 다 없으면 `금액 미정`.

### 재원 — `FUNDING_LABEL`

| 라벨 | 키 | 성질(종류에서 **파생**한다) |
|---|---|---|
| 국비 | `NATIONAL` | 현금 유입 · 회계 수익 |
| 지방비 | `LOCAL` | 현금 유입 · 회계 수익 |
| 자부담 현금 | `OWN_CASH` | 현금 유출 · 회계 수익 아님 · **별도 계좌** |
| 자부담 현물 | `IN_KIND` | 돈이 안 움직인다 — 「현물 제외」에서 빠지는 유일한 재원 |

~~자부담금~~ 금지 — 현금과 현물을 뭉개면 「현물 제외」가 설명되지 않는다.

### 현물 — `IN_KIND_LABEL` · `IN_KIND_BASIS_HINT`

| 라벨 | 키 | 환산 근거 기본 문구 |
|---|---|---|
| 인건비 | `LABOR` | 연봉 × 참여율 × 기간 |
| 장비사용료 | `EQUIPMENT` | 취득가 감가상각 또는 시간당 사용료 |
| 연구재료 | `MATERIAL` | 장부가 |
| 시설 | `FACILITY` | 면적 × 단가 × 기간 |

~~현물비~~ 금지 — 비용이 아니다. 환산 근거는 **정산 서류에 그대로 쓰인다.**

### 문형

| 자리 | 함수 |
|---|---|
| 부가세 방향 안내 | `taxBasisNote('GROSS')` |
| 현물 비중 | `inKindShare('260,000,000원', 20)` |
| 기간 없는 현물 | `undatedInKindNote(금액)` — 0으로 때우지 않았다는 사실을 밝힌다 |
| 연차·개월 | `yearLabel(2026)` · `monthsLabel(10)` |
| 명세 권한 없음 | `IN_KIND_LOCKED` — 무엇이 보이고 무엇이 안 보이는지 둘 다 말한다 |

## 5. 문장 — `lib/terms/sentence.ts`

| 자리 | 함수 | 예 |
|---|---|---|
| 빈 상태 제목 | `emptyTitle('deal')` | 딜이 아직 없어요 |
| 오류 | `failedTo('회의노트','만들지')` | 회의노트를 만들지 못했습니다. 잠시 후 다시 시도해 주세요. |
| 삭제 확인 | `confirmDelete('meeting',1,{…})` | 미팅 1건을 삭제할까요? 참석자 연결이 함께 사라지고, 회의노트 원본은 남습니다. |
| 진행 | `progress('올리는')` | 올리는 중… |
| 근거 부족 | `notEnough(...)` | 비교할 게시물이 3건뿐이라 배수를 내기 어려워요 |

**규칙 넷**
- **오류에 사과하지 않는다.** "죄송합니다"는 할 일을 안 알려 주면서 줄만 차지한다.
- **빈 상태는 "없어요"** — 탓하는 자리가 아니라 다음 행동을 권하는 자리다.
- **삭제 확인은 사라지는 것과 남는 것을 둘 다** 적는다(R-5).
- **섹션 제목은 명사구.** 대화체 금지 — ~~「이 날 할 수 있는 것」~~ ~~「지금 회의 중」~~ → 「미팅 기록」.

## 6. 가드가 막는 것 — `lib/ui/glossary.test.ts`

| # | 규칙 | 방식 |
|---|---|---|
| ① | 금지어(`BANNED_TERMS`)가 화면 문자열·JSX 텍스트에 새로 들어오는 것 | ratchet |
| ② | `app/**` 안의 새 라벨 맵 | ratchet |
| ③ | **내용까지 같은** 라벨 맵이 2곳 이상 | **즉시 차단** |
| ④ | 이름만 같은 라벨 맵이 느는 것 | ratchet |
| ⑤ | 금지어 표의 자기모순(대체어가 다시 금지어 / 이유 미기재) | 즉시 차단 |

**ratchet 인 이유**: 지금 금지어 위반이 **49파일**에 있다. 즉시 차단으로 걸면 `pnpm test` 가 통째로 빨개져 아무 일도 못 한다.
그래서 **"지금보다 늘면 차단"** 으로 걸고, 기존 것은 그 화면을 다른 일로 건드릴 때 함께 정리한다
(§2-6 (5) 목록 표준이 쓰는 방식과 같다). 줄면 baseline 이 자동으로 내려가 되돌아가지 못한다.
baseline: `scripts/.glossary-baseline.json` — **줄어든 날엔 함께 커밋한다.**

**③만 즉시 차단인 이유**: 내용까지 같으면 진짜 복붙이라 **하나를 고치면 나머지가 남는다.**
이름만 같은 것(`STATUS_LABEL` 이 게시 상태이기도 하고 공급사 상태이기도 하다)은 뜻이 다르므로 성격이 다르다.
