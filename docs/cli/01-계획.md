# 01 계획

## 판정
- 이 계획대로 하면 웹에서 되는 동작 859개 전부가 `teamda` CLI 로 되고, 새 라우트나 서버 액션은 정의 표에 한 줄(범위)만 더하면 CLI 에 같이 생긴다
- 조건: 키 범위 마이그레이션(318)을 운영 DB 에 적용하고 배포해야 운영에서 쓸 수 있음, 적용과 배포는 사용자 몫

## 구조

```
기능 정의 표 (apps/web/lib/actions/defs/*.ts, 동작마다 한 줄: 이름 범위 CLI 이름)
   │  scripts/cli/gen.mjs (cli:gen)
   ├─ 처리 함수 연결표 (apps/web/lib/actions/generated/loaders.ts, 정적 import 지연 로딩)
   ├─ docs/cli/02-기능대응표.md
   └─ packages/teamda-cli/src/generated/spec.json (빌드 때 넣는 명령 표)

요청 흐름
teamda CLI ── X-API-Key ──> /api/public/v1/<내부 경로> 또는 /api/public/v1/actions/<이름>
   [...path] 관문 (apps/web/lib/actions/dispatch.ts)
     1 키 인증, 만료, 분당 한도 (기존 publicApiAuth)
     2 정의 찾기, 범위 판정 (계정 권한 ∩ 키 범위)
        - 범위 밖 read write → 403 requiredScope
        - 범위 밖 approve send delete admin → 202 승인 요청
     3 쓰기: 쓰기 한도, Idempotency-Key, dryRun, 이전 값 읽기
     4 키 소유자 세션 문맥(AsyncLocalStorage) 안에서 **화면이 쓰는 그 처리 함수**를 그대로 부름
     5 감사(api_write_audit), 응답 봉투
```

- 처리 로직을 새로 쓰지 않음, 화면과 같은 함수를 부르므로 결과가 갈라질 수 없음
- createClient 와 getRequestUser 가 문맥을 보고 쿠키 대신 키 소유자 세션을 씀, 문맥은 관문만 엶
- 키 소유자 세션은 서비스롤 generateLink(magiclink) 다음 verifyOtp 로 만들고 사용자별로 메모리에 50분 둠
- 기존 공개 API 39개는 그대로 두고(하위 호환) 같은 경로의 빠진 메서드만 관문으로 넘김
- openapi.json 은 기존 표 + 정의 표에서 만들고 x-cli x-scope 를 실음
- CLI 는 명령을 손으로 안 씀, openapi.json(빌드 때 넣은 것 또는 teamda sync 로 받은 것)에서 명령 트리를 만듦

## 범위 판정 규칙 (정의 표 기본값, 손으로 덮어씀)
- admin: /api/admin, app/admin 서버 액션, 키 구성원 설정 자격증명
- delete: DELETE, 이름이 delete remove purge revoke 로 시작하는 서버 액션
- approve: approve decide commit confirm apply accept
- send: send mark-sent sign publish
- read: GET, get load list fetch search preview export 로 시작하는 서버 액션
- 나머지 write

## 새 의존성
- 웹: 없음 (AsyncLocalStorage 는 node 내장)
- CLI: 없음 (bun 내장 fetch, 자격 증명은 macOS security 명령과 Windows PowerShell CredRead 로 씀)

## 시험 환경
- 로컬 시험 DB 없음 (Docker 데몬 꺼짐), 쓰기 실DB 시험은 시험 DB 가 생기면 돌림
- 그 전까지: 관문 논리는 가짜 처리 함수로, CLI 는 가짜 서버로, 웹=CLI 는 「같은 처리 함수를 가리킴」으로 시험
- 운영에는 쓰지 않음
