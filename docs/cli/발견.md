# 발견

CLI 작업 중 본 화면과 API 문제, 이 작업에서 고치지 않음

- api_keys 표를 만든 마이그레이션이 저장소에 없음, 새 환경에서 마이그레이션만으로 DB 를 못 세움
- 감사 로그 CrmAuditLog 에 actorType API_KEY 가 없어 키로 한 변경이 사람 변경과 섞일 수 있음 (CLI 쪽은 api_write_audit 로 따로 남김)

## 견적서 서버 내보내기를 키로 부를 때 (P0158 I10, 해결 P0159 v0.11.62)
- 웹 세션으로 부르면 화면 미리보기 그대로 PDF PNG 가 나옴 (실측 2026-10-23, 1쪽 견적 PNG 9.6초 PDF 8.8초)
- 해결 전: teamda crm quote export 로 관문을 거치면 처리 함수에 쿠키가 없어 머리 없는 브라우저가 로그인 화면을 만났음
- 해결: 관문이 연 키 주인 문맥이면 그 사람 세션을 @supabase/ssr 쿠키 모양으로 머리 없는 브라우저에 심음 (lib/actions/acting-cookies.ts), 쿠키 경로는 그대로
- 2단계 인증을 켠 키 주인은 키 세션이 aal1 이라 화면이 /mfa 로 보냄, 굽기 전에 FORBIDDEN 과 안내 문구로 바로 거절함
- 같이 고친 것: teamda 가 파일 응답을 텍스트로 읽어 {"text":...} 로 감싸 깨뜨렸음, 이제 --out 경로에 바이트 그대로 씀
- 실측 2026-10-23 자기 dev 서버(:3259), 시험 계정 키로 관문 curl PDF 200 8.0초 PNG 200 8.6초, teamda --out 으로 PDF 1쪽 PNG 1588x2226, 예외 401 400 404 400 확인

## 굽다가 시간이 다 되면 오류 코드가 VALIDATION_FAILED 로 나감 (P0159 에서 봄)
- dev 서버 첫 컴파일이 길어 머리 없는 브라우저가 Navigation timeout 을 냈을 때 응답이 500 인데 code 는 VALIDATION_FAILED, 문구는 「요청을 처리하지 못했습니다」
- 입력 오류처럼 읽혀 부른 쪽이 다시 시도할지 판단하기 어려움, withCrmApi 의 알 수 없는 오류 분류 문제로 보임, 이 플랜에서는 고치지 않음
- 해결 (P0161, v0.11.66): 코드 목록에 INTERNAL(500) 을 더하고 withCrmApi 의 알 수 없는 실패가 그것을 씀, 문구는 그대로, 가드 lib/crm/domain/errors.test.ts
