# 영업 CRM — 처음 여는 사람의 관점에서 본 결함 분석

작성: 2026-08-17 · 대상 v0.7.534 · **분석만, 구현 없음**

---

## 0. 한 줄 결론

기능은 다 있는데 **제품이 아니다.**

지금 CRM 은 "만들어 둔 기능 12개가 사이드바에 나열된 상태"다. 처음 여는 사람이
**무엇부터 해야 하는지 아무도 알려 주지 않고**, 자기 회사와 상관없는 이름이 화면에 박혀 있는데
**그걸 지울 방법이 제품 안에 없다.**

원인은 하나로 모인다 — 나는 **기능 단위로 만들고 기능 단위로 검증**했다.
"이 기능이 되는가"는 매번 실브라우저로 확인했지만,
**"처음 온 사람이 이 화면에서 무엇을 하는가"는 한 번도 확인하지 않았다.**

---

## 1. 지적하신 것 — 사실 확인

### ① "카테고리 설정하는 곳이 어디야?"

**없습니다.** 코드로 확인한 사실:

| 무엇 | 지금 가능한 것 | 파일 |
|---|---|---|
| 파이프라인 목록 보기 | ✅ GET 만 있음 | `app/api/crm/pipelines/route.ts` — `export async function GET()` **단 하나** |
| 파이프라인 만들기 | ❌ POST 없음 | — |
| 파이프라인 이름 바꾸기 | ❌ PATCH 없음 | — |
| 파이프라인 지우기 | ❌ DELETE 없음 | — |
| 단계 추가·삭제·순서변경 | ❌ 없음 | `app/api/crm/stages/[id]/route.ts` 는 **PATCH 하나뿐**이고 그것도 진입 조건만 |
| 단계 진입 조건 | ✅ 가능 | `/crm/process` |

즉 `/crm/process` 화면은 이름이 "프로세스"인데 **실제로는 "진입 조건 설정"만** 한다.
파이프라인 자체는 **읽기 전용**이다. DB 를 직접 고치지 않는 한 바꿀 수 없다.

### ② "KDC 제품이라니 전혀 연관없는 내용인데"

기원: `apps/web/prisma/seed-data.ts:38`

```
파이프라인 4종 (TASKS T0-07 지정: GPU 인프라, 파트너십, 공공, KDC 제품)
```

**TASKS 문서에 그렇게 적혀 있어서 그대로 넣었습니다.**
그런데 실제 사용 현황은 이렇습니다:

| 파이프라인 | 단계 | 딜 |
|---|---|---|
| GPU 인프라 | 7개 | **1건** |
| 파트너십 | 6개 | 0건 |
| 공공 | 6개 | 0건 |
| KDC 제품 | 6개 | 0건 |

**4개 중 3개가 빈 껍데기**인데 딜 화면 탭 4칸, 리포트 세로 4블록을 차지합니다.
스크린샷에서 보신 "KDC 제품 · 진행 0건 · 성사 0건 · 실패 0건"이 그것입니다.

**제 잘못이 두 겹입니다:**
1. 문서에 적혔다는 이유로 **사업과 안 맞는 이름을 확인 없이** 시드에 넣었다
2. 넣어 놓고 **지울 길을 안 만들었다** — 이게 더 큰 잘못입니다

### ③ "딜에다가 등록하면 되는거야? 등록하는 곳이 닫혀있으면"

딜 화면(`/crm/deals`)의 등록 진입점은 **두 개**인데 둘 다 문제가 있습니다:

| 진입점 | 상태 | 문제 |
|---|---|---|
| "딜 추가" 버튼 | 보임 | 회사를 먼저 골라야 하는데 **회사가 없으면 아무것도 못 함** |
| "붙여넣기로 등록" | **접혀 있음** (`useState(false)`) | 제목만 보이고 눌러야 열림 — `QuickCreateBar.tsx:25` |

"붙여넣기로 등록"은 이 제품의 **가장 강력한 기능**(텍스트 붙여넣으면 회사·인물·딜을 한 번에)인데
**접어 놨습니다.** 처음 온 사람은 그게 뭔지 모르고 지나갑니다.

### ④ "그게 메뉴 중간쯤에 있으면 어떻게 하지?"

사이드바 순서 (`app/(crm)/layout.tsx`):

```
인박스 · 회사 · 인물 · 딜          ← 일상 동선
[기록]  미팅 · 할 일 · 기록 · 프로세스   ← 여기 "프로세스"
[분석]  리포트
[관리]  멤버 · 설정
[돌아가기] 홈 · 업무 · 캘린더
```

**설정해야 쓸 수 있는 것이 8번째·11번째에 있습니다.**
처음 온 사람은 위에서부터 누르는데, 1번(인박스)은 "AI가 찾아낸 제안"이라 **아직 아무것도 없고**,
정작 먼저 해야 할 파이프라인 정리는 목록 한참 아래 "프로세스"라는 이름으로 숨어 있습니다.

그리고 그 "프로세스"에 들어가도 **파이프라인은 못 바꿉니다**(①).

### ⑤ "사용자가 뭐부터 시작해야 하는지 모르겠는데?"

`/crm` 은 `/crm/inbox` 로 **바로 넘깁니다**(`app/(crm)/crm/page.tsx`).
그리고 인박스는 비어 있으면 이렇게 말합니다:

> "확인할 제안이 아직 없어요 — 미팅을 기록하거나 텍스트를 붙여 넣으면 AI가 회사·인물·딜 후보를 여기로 올립니다"

**설명은 맞는데 버튼이 없습니다.** "미팅을 기록하려면" 어디로 가야 하는지, 링크가 없습니다.

호스트 앱에는 실습형 온보딩(driver.js)이 있는데 **CRM 에는 없습니다** — 코드에 `onboarding` 이 0건입니다.

## 2. 지적하지 않으셨지만 같은 뿌리에서 나온 것

### ⑥ 빈 파이프라인이 모든 화면을 오염시킨다

딜이 0건인 파이프라인 3개가:
- 딜 화면: 탭 4칸 중 3칸 차지 → 누르면 빈 보드
- 리포트: 세로 블록 4개 중 3개가 "0건 0건 0건"
- 포캐스트: "성사율 아직 모름"이 단계마다 반복 → **화면 대부분이 "모름"**

빈 것을 접거나 숨기는 규칙이 없습니다. 표본이 얇으면 "모른다"고 말하는 규칙은 넣었는데,
**"아예 안 쓰는 것은 안 보여 준다"는 규칙은 없습니다.**

### ⑦ 첫 화면이 "받는 곳"이지 "하는 곳"이 아니다

인박스는 **AI가 넣어 준 것을 확인하는** 화면입니다.
그런데 처음 온 사람에게는 넣어 줄 AI 입력이 없습니다 — 회사도 미팅도 없으니까요.

즉 **가장 나중에 의미가 생기는 화면을 첫 화면으로** 뒀습니다.

### ⑧ "회사가 없으면 딜을 못 만든다"는 순서를 아무도 안 알려 준다

딜 만들기 모달은 `companyId` 를 필수로 받습니다(스키마상 `companyId String` — nullable 아님).
그런데 딜 화면 어디에도 "회사를 먼저 만드세요"라는 말이 없습니다.
처음 온 사람은 "딜 추가"를 누르고 회사 드롭다운이 비어 있는 걸 보고 멈춥니다.

### ⑨ 시드 데이터가 "예시"인지 "내 데이터"인지 구분이 없다

회사 12건은 옛 시스템에서 이관한 **진짜 데이터**이고,
파이프라인 4개는 제가 넣은 **예시**입니다.
화면에서는 둘이 똑같이 보입니다. 사용자는 "이거 지워도 되나?"를 알 수 없습니다.

### ⑩ 설정 화면이 "관리자 설정"과 "내 워크스페이스 구성"을 안 나눈다

`/crm/settings` 에 지금 카드가 7개 있습니다:
예산 · AI 모델 · 자동 반영 · 연동 · 중복 정리 · 자동화 · 들여오기 · 내보내기

이 중 **처음에 반드시 손대야 하는 것**(파이프라인 구성)은 아예 없고,
**나중에나 쓸 것**(AI 예산, 중복 정리)이 위에 있습니다.

### ⑪ 기획서가 요구한 것을 제가 빠뜨렸다

통합기획서 v0.2.1 로드맵 **Phase 1 6번**:

> "다중 파이프라인과 진입 조건, **프로세스 캔버스 1차(보기와 편집)**"

권한 매트릭스 874행:

> "설정, 필드, **파이프라인** | Owner O | Admin O | Member X | ReadOnly X"

**기획서는 파이프라인을 관리자가 편집하는 대상으로 명시했습니다.**
제가 "진입 조건"만 만들고 파이프라인 자체는 읽기 전용으로 뒀습니다.
TASKS 문서의 T1 목록에 그 항목이 명시적으로 없다는 이유로 넘어간 것이고,
**이건 제가 범위를 좁게 읽은 것**입니다.

## 3. 왜 이렇게 됐나 — 근본 원인

### 원인 1. 검증 단위가 "기능"이었지 "첫 사용"이 아니었다

저는 매번 이렇게 검증했습니다:

> 규칙을 만든다 → 딜을 옮긴다 → 할 일이 생긴다 ✅

이건 **이미 데이터가 있고 설정이 끝난 사람**의 경로입니다.
**아무것도 없는 사람이 처음 열었을 때**를 한 번도 밟지 않았습니다.

E-1~E-5 완료 조건은 "실브라우저에서 데이터를 넣고 확인"을 요구하는데,
저는 그 "데이터를 넣고"를 **API 로** 했습니다. 화면의 첫 진입점을 통해 넣은 게 아니라요.

### 원인 2. 문서를 사실 확인 없이 구현으로 옮겼다

"KDC 제품"은 TASKS 에 적혀 있었습니다. 그래서 넣었습니다.
그게 실제 사업과 맞는지는 **한 번도 묻지 않았습니다.**

시드 데이터는 사용자가 지우기 전까지 **영원히 남는 제품의 일부**인데,
저는 그걸 "문서대로 채운 초기값" 정도로 다뤘습니다.

### 원인 3. "만들 수 있는 것"과 "지울 수 있는 것"을 짝으로 안 봤다

이 세션에서 저는 "만들어 놓고 안 부르는" 결함을 여섯 번 잡았습니다.
그런데 **"넣어 놓고 못 지우는"** 결함은 못 봤습니다 — 같은 종류인데요.

파이프라인·단계는 시드로 넣었으니 **지우는 길도 같이 만들었어야** 합니다.

### 원인 4. 정보 구조를 "기능 분류"로 짰다

사이드바를 기록/분석/관리로 묶은 것은 **개발자가 보는 분류**입니다.
사용자가 보는 분류는 "지금 해야 할 것 / 자주 보는 것 / 가끔 설정하는 것"입니다.

그래서 **처음에 반드시 해야 하는 것**(파이프라인 정리)이 "관리"도 아닌 "기록" 그룹에
"프로세스"라는 이름으로 들어가 있습니다.

## 4. 무엇을 만들어야 하는가 — 기획

우선순위는 **처음 여는 사람이 막히는 순서**로 매겼습니다.

### P0-1. 파이프라인 관리 (없어서 못 지움)

**무엇**: 파이프라인·단계를 만들고 이름 바꾸고 순서 바꾸고 지우는 화면.

**어디**: `/crm/process` 를 확장. 지금 진입 조건만 있는 화면에 파이프라인 자체를 올린다.
이름도 "프로세스"보다 **"영업 단계"**가 사람의 말에 가깝다.

**규칙**:
- 딜이 **한 건이라도 있는** 파이프라인은 지울 수 없다 → 대신 **"안 씀"으로 감추기**
  (지우면 그 딜들이 갈 곳이 없다. 감추면 되돌릴 수 있다)
- 딜이 0건이면 진짜 삭제 가능
- 단계 삭제도 같은 규칙 — 그 단계에 딜이 있으면 **"어디로 옮길지"를 먼저 묻는다**
- 마지막 파이프라인은 못 지운다(딜을 만들 곳이 없어진다)
- 성사·실패 단계는 못 지운다(딜을 닫을 곳이 없어진다)

**API**: `POST/PATCH/DELETE /api/crm/pipelines`, `POST/PATCH/DELETE /api/crm/stages`
전부 ADMIN — 기획서 권한 매트릭스 그대로.

### P0-2. 첫 실행 화면 (뭐부터 할지 모름)

**무엇**: `/crm` 이 인박스로 넘기지 않고, **아직 준비가 안 된 워크스페이스면 시작 화면**을 보여준다.

**판정**: 회사 0건이거나 딜 0건이면 "아직 시작 전"으로 본다.

**화면**: 할 일 3개를 순서대로, **각각 버튼과 함께**

```
1. 영업 단계를 우리 회사에 맞게 정리하세요
   지금 4개가 있는데 3개는 안 쓰고 있어요       [정리하러 가기]

2. 회사를 등록하세요
   엑셀이 있으면 한 번에 들여올 수 있어요        [엑셀 올리기] [하나씩 만들기]

3. 첫 딜을 만들어 보세요
   회사를 고르고 금액과 마감만 넣으면 됩니다      [딜 만들기]
```

각 항목은 **끝나면 자동으로 체크**된다(회사가 생기면 2번이 완료로 바뀐다).
셋 다 끝나면 이 화면은 사라지고 인박스로 간다.

**왜 온보딩 투어(driver.js)가 아니라 체크리스트인가**:
투어는 한 번 보고 끝나고, 중간에 나가면 다시 못 찾는다.
체크리스트는 **상태**라서 언제 돌아와도 어디까지 했는지 보인다.

### P0-3. 시드 파이프라인 정리 (사업과 안 맞음)

**무엇**: "KDC 제품 · 공공 · 파트너십"을 어떻게 할지는 **사용자만 아는 사실**이다.
제가 임의로 지우면 안 된다.

**그래서**: P0-1 이 생기면 사용자가 직접 지운다.
다만 **처음 시드를 1개로 줄이는 것**은 제안한다 — 새 워크스페이스는 "기본" 하나로 시작하고,
필요하면 사용자가 늘리는 편이 낫다. 4개를 주고 3개를 지우게 하는 것보다.

**⚠️ 지금 있는 데이터는 승인 없이 안 건드립니다.**

### P1-1. 빈 파이프라인을 화면에서 접기

- 딜 화면 탭: 딜 0건인 파이프라인은 **"안 쓰는 것 3개 보기"**로 접는다
- 리포트: 딜 0건이면 한 줄로 접고, 펼치면 보인다
- 지금처럼 빈 블록이 화면을 채우면 **있는 정보가 안 보인다**

### P1-2. "붙여넣기로 등록"을 펼쳐 놓기

이 제품의 가장 강한 기능인데 접혀 있다.
**딜이 0건일 때는 펼친 채**로 두고, 딜이 생기면 접는다.

### P1-3. 사이드바를 사용자 동선으로 다시 묶기

```
지금                          제안
────────────────────         ────────────────────
인박스 회사 인물 딜            [매일] 인박스 · 딜 · 회사 · 인물
[기록] 미팅 할일 기록 프로세스   [기록] 미팅 · 할 일
[분석] 리포트                 [보기] 리포트 · 기록
[관리] 멤버 설정              [설정] 영업 단계 · 멤버 · 설정
```

- "프로세스"를 **"영업 단계"**로 바꾸고 [설정] 그룹으로 올린다
- "기록"이 두 번 나온다(그룹 이름 "기록" 안에 항목 "기록") — 항목을 **"변경 이력"**으로
- 딜을 회사보다 앞에 — 영업이 매일 보는 것은 딜이다

### P1-4. 딜 만들기에서 회사가 없으면 그 자리에서 만들기

지금은 회사 드롭다운이 비면 막힌다.
**"+ 새 회사"**를 드롭다운 안에 넣어 그 자리에서 만들 수 있게.

### P2-1. 예시 데이터와 내 데이터 구분

시드로 넣은 것에 표시를 남기고(`source: 'SEED'`), 첫 실행 화면에서
"예시로 넣어 둔 것 3개 — 안 쓰면 지우세요"라고 말한다.

## 5. 하지 말아야 할 것

- **파이프라인을 지금 임의로 지우는 것** — 사용자만 아는 사실이다
- **온보딩 투어(driver.js)를 CRM 에 이식** — 호스트 것을 복제하면 두 벌이 된다.
  체크리스트가 더 낫고 더 싸다
- **파이프라인 편집을 새 화면으로 신설** — `/crm/process` 가 이미 그 자리다.
  화면을 늘리면 "어디서 하는지" 문제가 다시 생긴다

## 6. 순서와 규모

| 순서 | 무엇 | 왜 이 순서 | 규모 |
|---|---|---|---|
| 1 | P0-1 파이프라인 관리 | 이게 없으면 KDC 를 못 지운다 | API 6개 + 화면 1개 확장 |

## 7. 이번 일에서 정책으로 올려야 할 것

이 저장소는 "만들어 놓고 안 부르는" 결함을 반복해 왔고 그걸 가드로 잡아 왔다.
이번에 드러난 것은 **그 짝**이다:

> **넣을 수 있으면 지울 수 있어야 한다.**
> 시드로 넣은 것, 자동으로 만들어지는 것, 예시로 채운 것 —
> 전부 **제품 안에서 지우거나 감출 길**이 함께 있어야 한다.
> 없으면 사용자는 DB 를 고쳐 달라고 개발자를 부른다.

그리고 검증 규칙에 하나 더:

> **첫 사용을 밟는다.**
> 기능 검증은 "데이터가 있는 상태"에서 하지만,
> 화면 검증은 **"아무것도 없는 상태에서 처음 연 사람"**으로 한 번 더 밟는다.
> 그 사람이 30초 안에 다음 행동을 못 찾으면 그건 미완이다.
