# GPU 가격표 "모델 표시 정체성" 진단·재기획 (구현 없음 — 기획 전용)

작성: 2026-07-26 · 기준 버전 v0.7.405 · 🟦 DC-ANA(실경로 진단) + 🟦 DC-BIZ(fable5, 전략) + 실DB 확정

## 사용자 좌절 (원문)
"H100, H200, RTX3060 이런식으로만 깔끔하게 나왔으면. TESLA는 거의 취급 안 하는데 잔뜩 있고, 6000류는 중복 다수. 정렬도 ABC순 말고 최신 모델 순으로. 이 상태면 처음부터 다시 기획해야 하나."

## 결론 한 줄
**재기획 불필요. 엔진은 멀쩡하고, 없는 건 "무엇을 보여줄지 고르는 큐레이션 레이어"뿐이다. P0(노출 정책)만 얹어도 좌절의 70%가 사라진다.**

## 1. 확정된 사실 (코드 + 실DB, 추측 아님)

### 실 렌더 경로 (CLAUDE.md "실 렌더 경로 우선" 준수 확인)
- `/pricing/gpu` 기본 탭 → `UnifiedTableConnected`(플래그 `unified` DEFAULT_ON) → API `/api/pricing/gpu/cockpit` → `getGpuCatalog()` (`lib/gpu/pricing.ts:174`) → `UnifiedTable`
- `PriceTableTab`은 `!unifiedOn` 죽은 경로(롤백용). **수정은 UnifiedTable 계열에 해야 함.**

### 그룹핑 엔진은 이미 정상
- 그룹핑 SSOT `baseModelKey()` (`canonical-model.ts:134`)가 폼팩터(SXM/PCIe/NVL)를 이미 합침 → `H100 SXM/PCIe/NVL` → **"H100" 1그룹**. 즉 사용자가 걱정한 "파편화"는 그룹핑 버그가 아님.

### 유일한 노출 정책 = `deleted_at IS NULL` (그게 전부)
- `pricing.ts:178`은 `.is('deleted_at', null)` 하나만 건다. `is_active`/`featured`/`show_in_table` **컬럼 자체가 gpu_products에 없음**(마이그 024·025·166 전수 확인).
- 결과: 취급하든 안 하든 **활성 99행 전량 노출**.

### 실 데이터 (gpu_products, 활성 99행 / 약 72 모델)
| 신호 | 값 |
|---|---|
| 우리 판매가(strategic_price_krw) 설정 | **단 7행** |
| 공급견적(supply_quotes) 보유 product | 73개 |
| TESLA 계열 | **10행** = K40·K80·M10·M40·M60·P100·P4·P40·P6 (2014~2018 구형, 명백 미취급) |
| "6000" 계열 | Quadro RTX 6000(24GB)·RTX 6000(96GB)·RTX 6000 Ada(48GB)·RTX A6000(48GB)·RTX Pro 6000(48/96GB) |

- "6000"은 **대부분 실제로 다른 GPU** → 병합 대상 아님, 표기 정리 대상. 유일 병합 후보 `RTX 6000`(96GB) ↔ `RTX Pro 6000`(96GB) 동일제품 의심 + `Pro`/`PRO` 대소문자 혼재.

### 정렬
- `UnifiedTable.tsx:101` `defaultCmp` = 모델명 알파벳순(numeric) 하드코딩. **최신순에 필요한 세대/출시연도 데이터가 코드·스키마에 없음.**

## 2. 재기획 vs 살리기 → **살리기** (🟦 DC-BIZ 판정)
좌절 3가지를 분해하면 엔진 결함은 0건. baseModelKey 그룹핑·supply_quotes 연결·dedup·tier-dict·merge RPC·소프트삭제(v0.7.405)까지 검증된 자산이 이미 작동 중. 전면 재설계 = 이 자산을 버리고 같은 문제를 다시 푸는 것 → 비용 대비 효과 음수. 현 구조 위에 **(i) 노출 정책 + (ii) 정렬 축** 둘만 얹으면 사용자가 원한 화면이 나온다.

## 3. 설계 결정

### 3-1. 취급 여부 판정 → **(d) 하이브리드** (수동 플래그 SSOT + 자동 시드)
- (b) strategic_price 자동 = 7행만 남아 **과소 노출**(RTX3060조차 탈락 위험). (c) supply_quotes 자동 = 73행 남아 **과대 노출**(구형 TESLA도 과거 견적 있으면 통과, 필터 무의미).
- **추천**: "취급 여부"는 영업 의사결정이지 데이터 유도값이 아니다. 신규 **노출 플래그(수동, SSOT)** 신설 → 초기값을 자동 시드(strategic_price 있음 OR 최근 견적 있음 → ON 후보 제시)하고 admin이 1회 확정 → 이후 토글 유지.
- **신규 유입 모델 기본값**: "숨김 + 검토 배지" 제안 (견적서에서 추출된 신모델이 조용히 묻히면 안 됨). ← **사용자 확정 필요**

### 3-2. 최신순 정렬 → **아키텍처 세대 랭크 딕셔너리 (lib SSOT, 마이그 불필요)**
- 영업이 말하는 "최신" = 출시일 아니라 세대: Blackwell > Hopper > Ada > Ampere > Turing > Volta > Pascal > Kepler.
- 세대는 ~10개뿐, 모델명으로 판정 가능, 분기 단위로만 변함 → `tier-dict.ts` 선례처럼 **lib 딕셔너리(코드 SSOT)** 가 실용적. DB 컬럼은 유지비만 늘고 이득 없음(외부 API 소비자 생기면 그때 승격 검토).
- 세대 동률 내 2차 정렬 = tier/메모리.

### 3-3. 6000/TESLA 정리 → **숨김(비노출) 원칙, 삭제는 확인된 진짜 중복에만**
- TESLA 10행 = **숨김**(시장가 관측·견적 이력 데이터 가치 있음, 미취급은 카탈로그 상태이지 데이터 소멸 사유 아님, 토글로 가역).
- 6000류 = 표기 캐노니컬라이즈(Pro/PRO 통일). `RTX 6000`96GB↔`Pro 6000`96GB는 **사람 확인 후에만** 기존 `merge_gpu_products_apply` RPC(무손실 선례)로 병합.
- 소프트삭제 인프라(v0.7.405)가 이미 있어 신설 불필요.

## 5. 리스크 (🟦 DC-BIZ)
1. **노출 필터의 계층 오염** — 필터는 **표시 계층(카탈로그/콕핏 뷰)에만**. 시세 수집·경쟁사 매칭·resolveProductId 등 데이터 SSOT 경로에 스며들면 숨긴 모델의 시장 관측이 끊기고 깡통/중복 재생성(v0.7.264 사고 계열) 재발.
2. **과병합** — 6000류는 이름만 비슷한 별개 제품 다수. 스펙(메모리·아키텍처) 불일치 시 병합 금지, 의심 건은 반드시 사람 확정 게이트.

## 6. 영업 관점 부가가치
"취급 모델만 + 최신순" 화면은 그대로 **고객 미팅용 상품 카탈로그**로 승격 가능. 노출 플래그·세대랭크는 향후 gcube.ai 공개 가격페이지·외부 API 상품 목록에 재사용됨. 전면 재기획은 이 재사용 시점을 수개월 미룸.

## 7. 사용자 확정 완료 (2026-07-26 Q&A) — 구현 착수 시 이 결정 준수
1. **신규 유입 모델 기본 노출값 = 숨김 + "검토 대기" 배지.** admin이 검토 후 노출 확정. (견적서에서 추출된 신모델이 조용히 묻히지 않도록)
2. **자동 시드 "최근 견적" 범위 = 시스템 고정 금지.** 특정 일수/개월을 코드에 하드코딩하지 말 것. admin이 직접 조정 가능한 설정값으로 두거나, 시드는 "판매가 있음 OR 견적 있음"의 넓은 후보만 제시하고 최종 판단은 사람이. (사용자: "그건 알아서 바꿀게, 시스템으로 제한하지 마")
3. **기본 뷰 = 전원 동일 ("취급만" 기본).** admin/일반 구분 없이 기본은 취급 모델만. (admin은 관리 UI에서 전체 접근)
4. **착수 범위 = P0 + P1 + P2 전부.** 단, 각 단계는 독립 배포 가능하게 순차 진행.

## 8. 구현 완료 (v0.7.406, 2026-07-27)
사용자 "구현진행해 멈추지말고" → P0+P1+P2 구현.

**마이그레이션 180** (prod 적용 완료): `is_active`(기본노출)·`needs_review`(검토대기) 컬럼 신설 + 부분 인덱스 + 감사 CHECK에 `product_visibility_changed` 추가. 시드 결과 = 활성 99행 중 **88 노출 / 11 숨김(TESLA 10 + Quadro RTX 6000 1)**, needs_review=0(기존 전부 검토완료 베이스라인). 신규 유입 기본값 = is_active=false + needs_review=true.

**P0 노출 정책**:
- `getGpuCatalog`(pricing.ts)는 컬럼만 select 추가, **필터 없음**(전량 반환) → 공개API·시세·매칭 SSOT 무오염.
- 필터는 **표시 계층(UnifiedTable)에서만**: 기본 "취급만"(is_active), "전체 보기" 토글(+숨김 개수), 검토대기/숨김 배지.
- admin 관리: 그룹 헤더 "숨기기/노출" 토글 → `PATCH /api/pricing/gpu/models`(requireAdminApi, UUID검증, 감사기록). 전원 기본 "취급만" 동일.

**P1 최신순**: `lib/gpu/generation.ts`(세대 랭크 SSOT, 마이그 불필요) + UnifiedTable "최신순/이름순" 토글(기본 최신순). Blackwell>Hopper>Ada>Ampere>Turing>Volta>Pascal>Maxwell>Kepler.

**P2 표기**: `canonicalDisplayName`으로 "RTX Pro"→"RTX PRO" 통일. TESLA는 시드로 기본 숨김. **6000 중복(RTX6000 96GB↔Pro6000 96GB) 자동병합은 미실행** — 사람 확정 게이트(admin이 기존 병합 UI로 처리).

**검증**: tsc·lint·design:check 통과, 단위 1348건 전부 통과(generation 11건 신규). ⚠️ **admin 실브라우저 E2E는 세션 부재로 미검증** — 로그인 후 재확인 권장.

**미적용 범위(의도)**: 공개 API(/api/public/v1/products)는 여전히 전량 노출(내부 큐레이션 미반영) — 필요 시 후속.
