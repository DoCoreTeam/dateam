## 承 — 원인 하나

### 문서가 코드에서 나오지 않는다

`app/develop/page.tsx`는 **940줄짜리 손으로 쓴 JSX**다. 엔드포인트를 추가해도 문서는 저절로 늘지 않고,
문서를 고쳐도 코드는 변하지 않는다. **둘이 어긋나도 아무 일도 일어나지 않는다.**

결정적 대목: 이 화면에서 **유일하게 안 썩은 부분**이 7개 언어 코드 예시인데,
그건 `lib/api-docs/snippets.ts`(227줄)가 `RequestSpec` 하나에서 **결정적으로 생성**하기 때문이다.
**우리는 이미 답을 갖고 있었고, 그걸 코드 예시에만 쓰고 엔드포인트에는 안 썼다.**

| 증상 | 원인 |
|---|---|
| 한도를 「약속만」 했다 | 문서와 코드를 잇는 장치가 없어서 |
| 「156개」가 굳었다 | 숫자가 데이터가 아니라 문자열이라서 |
| 봉투가 두 벌이다 | 응답을 한 곳에서 만들지 않아서 |
| 폐기된 말이 남았다 | 화면이 한글 문자열을 직접 적어서 |
| 새 CRM에 문이 없다 | 문 하나 = 라우트 + 940줄 수기 편집이라 비용이 커서 |
| 사용량이 항상 1이다 | 아무도 그 숫자를 화면에서 볼 일이 없어서 |
| 소유권 검사가 0건이다 | 쓰는 사람이 우리뿐이라 한 번도 아프지 않아서 |

**이 결함들은 실사용자가 0명이라 지금까지 아무 피해도 없었다.
바꿔 말하면 손님을 받는 순간 전부 동시에 터진다.** 그래서 순서가 「문을 넓힌다」로 시작하면 안 된다.

## 轉 — 순서

거짓말을 끄고 → 문을 시스템으로 만들고 → 문을 넓히고 → 손님을 받는다.

### S0 · 새는 것을 막고 거짓말을 끈다 — 지금 바로, 승인 불필요

- F-1·F-2 소유권 검사: 세 리소스의 PATCH/DELETE에 `eq('user_id', ctx.userId)` + GET 목록 스코프
- F-3 평문 비밀번호: 컬럼 비우기 + 저장 중단(승인 2건은 이미 무의미)
- F-4 문서: 한도 섹션을 **구현 전까지 「준비 중」**으로 표시 (약속 철회)
- F-6 신청 문구: 「승인되면 관리자가 직접 연락드립니다」로 사실화
- F-7 CORS: 서버 전용 명시, 데모 화면은 서버 프록시 경유
- F-9 「156개」 → 취급 기준 숫자를 데이터에서

**왜 먼저인가** — 손님이 0명인 지금이 소유권 규칙을 바꿔도 아무도 안 깨지는 **유일한 시점**이다.
한 명이라도 붙은 뒤엔 이게 파괴적 변경이 된다.

### S1 · 약속한 한도를 실제로 지킨다

- `X-RateLimit-Limit / Remaining / Reset` 헤더 + 429 + `Retry-After`
- F-5 호출 수를 DB에서 원자적으로 증가 (fire-and-forget 제거)
- 카운터는 **새 인프라 없이** `api_keys` 옆 분 단위 테이블 + 원자적 `upsert` (⑤ 참조)

### S2 · 문서를 코드에서 뽑는다 — **핵심 단계**

- `lib/api-docs/registry.ts` = 엔드포인트 SSOT(경로·메서드·파라미터·응답·예시)
- `/develop`은 렌더만. `/api/public/v1/openapi.json`도 같은 곳에서 생성
- 가드: 라우트 파일 ↔ registry 불일치 시 `pnpm test` 실패 (양방향)
- F-12 화면 재작성을 여기서 함께 (별도 과제로 떼면 영원히 안 한다)

**왜 지금인가** — S4에서 문을 수십 개 뚫는다. 지금 뚫으면 수기 부채가 수십 배가 되고
정확히 그 이유로 다시 방치된다. **이 단계를 건너뛰면 1년 뒤 같은 보고서를 다시 쓴다.**

### S3 · 봉투와 말을 한 벌로

- `respond()` SSOT → 전 공개 라우트 `meta{}` 통일. 기존 최상위 필드는 **당분간 병행 출력**(M-4 추가 전용)
- 금지어 66곳 → `@/lib/terms`

### S4 · 문을 넓힌다 — 선행 조건 있음(②)

- **읽기 우선**: 회사·인물·딜·미팅·견적·할 일 / 채널·게시물·주제·트렌드 / 회의 기록·요약
- **쓰기는 딜·미팅부터**(③ 참조) — `lead-import`·`quick-create`가 이미 안쪽에 있다
- 구 `accounts·contacts·deals`는 **지우지 않고** 문서에서 「이관 중」 표시 + 새 경로 안내

### S5 · 손님을 받는다 — 선행 조건 있음(①)

- 신청·승인·키 발급·한도 임박·폐기 예고 메일
- `/api-keys` 안에 사용량·최근 오류·한도 잔량 (④ 참조 — 새 화면 금지)
- 웹훅(딜 단계 변경·새 게시물) · API 변경 이력 · 폐기 정책

## 승인 시 진행

1. **S0 → S1 → S2 → S3**을 한 흐름으로. 전부 되돌릴 수 있는 변경이라 중간에 멈출 이유가 없다
2. **S4**는 ②의 기본값(사내 자동화 · 읽기 + 키 주인 범위)으로. 파트너 판매용이면 조직 격리를 선행 과제로 승격
3. **S5**는 메일 장치를 붙이는 시점에 시작. 그전까지 신청 화면은 사실만 말한다
4. 단계마다 **G1 · G2 · G3**를 거치고 커밋은 단계별로 분리

## 이 감사가 안 본 것

- `/api-keys`·`/admin/api` 화면의 실동작(브라우저 검증 미실시 — 읽기 감사만)
- 공개 API의 실제 응답값(키를 새로 발급하지 않았다. 운영 데이터 오염 회피)
- CI·회의 도메인의 **개별** 엔드포인트가 외부 공개에 적합한지(도메인 단위로만 봤다)
