## 공통 조건 바 (탭 간 유지)

`주제 | 플랫폼 | 포맷 | 기간(기본 28일) | 채널(내 채널 다중 선택)`
URL 쿼리로 보존한다. 트렌드(R04)의 조건 바와 **동일 컴포넌트**를 쓴다(중복 구현 금지).

모든 수치에는 기준을 병기한다 — `28일 기준, 표본 42건` (설계서 §6.6 정상 상태 규칙).

## 탭 1 — 내 콘텐츠 (`?tab=mine`)

내 채널(`ownership='owned'`)의 게시물이 평소 대비 어땠는지.

### 영역
```
┌─────────────────────────────────────────────┐
│ 요약 4칸: 게시 12건 · 평소 대비 중앙값 1.4배 │
│           최고 8.4배 · 추적 중 5건            │
├──────────────────────┬──────────────────────┤
│ 추이 차트            │ 상위/하위 5건        │
│ (게시물별 배수 점,   │ (배수 순, 카드)      │
│  기간 창 내)         │                      │
├──────────────────────┴──────────────────────┤
│ 게시물 표 (13px 밀도 구간)                   │
└─────────────────────────────────────────────┘
```

### 표시 필드 (표)
| 열 | 원천 | 비고 |
|---|---|---|
| 썸네일·제목 | `ci_contents` | 2줄 말줄임 |
| 플랫폼 | `platform` | 아이콘만(브랜드 색 허용) |
| 게시일 | `published_at` | KST 변환 필수 |
| 조회수 | 최신 `ci_content_metrics.views` | `tabular-nums` |
| 평소 대비 | `ci_content_derived.outlier_index` | `baseline_n < 8`이면 `—` + 툴팁 `비교 이력 부족` |
| 같은 주제 상위 | `topic_percentile` | 모집단 30 미만이면 `—` |
| 조회 속도 | `velocity_per_hour` | 스냅샷 2점 이상일 때만 |
| 신뢰도 | `confidence` | StatusBadge |
| 게시 경로 | `ci_publications.route` | `수동`/`API` |

### 액션
행 클릭 → 공용 `DetailSheet` · 수치 클릭 → `EvidenceSheet`(포함 표본·제외 사유·수집 방법) ·
`이 성과로 공식 찾기`(→ 학습 탭) · CSV 내보내기

### 빈 상태
> **아직 추적 중인 내 게시물이 없습니다.**
> 게시에서 URL을 입력하면 그 시점부터 성과가 쌓입니다. 과거 게시물도 URL만 붙여넣으면 소급 추적됩니다.
> `[게시로 이동]` `[URL 붙여넣기]`

## 탭 2 — 시장 대비 (`?tab=market`)

같은 주제 시장에서 내 콘텐츠가 어디쯤인지. **모니터링 코퍼스만** 모집단으로 쓴다(`source='monitoring'`).

### 영역
```
┌─────────────────────────────────────────────┐
│ 내 위치: 같은 주제 상위 18% (표본 340건)     │
├──────────────────────┬──────────────────────┤
│ 분포 차트            │ 규모 밴드별 비교     │
│ (시장 배수 분포 +    │ (내 채널 규모 밴드   │
│  내 게시물 위치 표시)│  안에서의 위치)      │
├──────────────────────┴──────────────────────┤
│ 나보다 잘된 콘텐츠 (배수 순, 아이디어 만들기)│
└─────────────────────────────────────────────┘
```

### 표시 필드
분포 차트는 중립 팔레트(`--ci-chart-*`)만 사용하고 내 게시물만 `--brand`로 강조.
비교 가능성이 B/C인 표본은 조회수 축에서 제외하고 배지로 사유를 밝힌다.

### 데이터 규칙
- 모집단 30건 미만이면 차트 대신 `데이터 부족` 안내 + 관심 채널 추가 유도.
- 플랫폼 혼합 시 `comparability_class` 강등 규칙 적용(§02 문서 2-3).

### 액션
`아이디어 만들기`(다음 단계) · `보드 담기` · `이 채널 모니터링 추가`

### 빈 상태
> **비교할 시장 데이터가 아직 없습니다.**
> 관심 채널을 3곳 이상 등록하면 같은 주제 시장에서의 내 위치가 여기 표시됩니다.
> `[관심 채널 추가]`

## 탭 3 — 학습 (`?tab=learning`)

"다음 추천에 반영된 내역" — 루프가 닫혔음을 사용자가 눈으로 확인하는 화면.

### 영역
```
┌─────────────────────────────────────────────┐
│ 반영 요약: 새 공식 2개 · 갱신 5개 · 규칙 승격 1개│
├─────────────────────────────────────────────┤
│ 내 성과에서 확인된 공식                      │
│  · 제목에 숫자를 넣으면 중앙값 2.1배         │
│    (근거 32개, 채널 7곳) [근거 보기]         │
├─────────────────────────────────────────────┤
│ 내 정정이 만든 변화 (ci_corrections)         │
│  · 주제 정정 12건 → 분류 예시로 반영         │
│  · 반복 정정 3건 → 제외 규칙 승격 제안 [검토]│
├─────────────────────────────────────────────┤
│ 분류 품질: 자동 확정률 87% · 검토 큐 13%     │
└─────────────────────────────────────────────┘
```

### 표시 필드
| 항목 | 원천 |
|---|---|
| 공식 문장·배수·근거 수·채널 수 | `ci_patterns` (승격 기준 미달분은 표시하지 않음) |
| 정정 건수·종류 | `ci_corrections` 집계 |
| 승격 제안 | 동일 정정 반복 감지분, 승인 시 `ci_topic_rules(origin='promoted')` 생성 |
| 자동 확정률·검토 큐 유입률 | `ci_contents.topic_source` 분포 (SLO 대조) |

### 액션
`근거 보기`(EvidenceSheet) · `공식 보관`(archive) · `규칙 승격 승인/거절` ·
`이 공식으로 아이디어 만들기`

승격 승인은 분류 동작을 바꾸는 되돌리기 어려운 변경이므로 **확인 절차**를 둔다.

### 빈 상태
> **아직 학습에 쓸 데이터가 모이지 않았습니다.**
> 게시물 성과가 쌓이고 분류를 몇 번 정정하면, 무엇이 반영되었는지 여기에 표시됩니다.
> `[성과 보기]`

## 5상태 (설계서 §6.6, 전 탭 공통)

| 상태 | 이 화면에서의 구현 |
|---|---|
| 로딩 | 요약 4칸·차트·표 골격 스켈레톤. 스피너 금지 |
| 빈 상태 | 위 탭별 문구 + 다음 행동 버튼 1개. 일러스트 없음 |
| 부분 데이터 | 수치 자리에 `—` + `일부만 수집됨` 배지, 탭하면 `missing_fields`. 추정값 위장 금지 |
| 오류 | 원인 코드 + 재시도 버튼 + 문의 경로. 차트만 실패해도 표는 살린다 |
| 정상 | 모든 수치에 기간 창·표본 수 병기 |

## 데이터 소스 요약

| 화면 요소 | 테이블 |
|---|---|
| 내 게시물 | `ci_contents` ⨝ `ci_channels(ownership='owned')` |
| 배수·백분위·속도 | `ci_content_derived` |
| 추이·조회수 | `ci_content_metrics` |
| 시장 모집단 | `ci_contents(source='monitoring', is_stat_excluded=false)` |
| 공식 | `ci_patterns` + `ci_pattern_evidence` |
| 정정 이력 | `ci_corrections` |
| 게시 경로 | `ci_publications` |

집계 쿼리는 전부 `lib/ci/corpus.ts`의 `CORPUS_FILTER`를 경유한다 — 화면마다 조건 복붙 금지.
