# 콘텐츠 인텔리전스 CRUD 전수 조사 — 무엇을 지우고 고칠 수 있나

작성 2026-08-16 · 기준 v0.7.492 · **조사 문서. 구현 없음.**

---

## 0. 한 줄

**만들 수는 있는데 지울 수가 없다.** CI 화면 전체에서 삭제 버튼이 있는 것은 **자료·이슈 2종뿐**이고,
이 제품의 중심인 **콘텐츠는 수정도 삭제도 API 자체가 없다.**

사용자가 가리킨 화면(수집함 → 실패 탭)에는 재시도(↺)와 원본 열기(↗)만 있다.
잘못 들어온 게시물을 **지울 방법이 없다.**

---

## 1. 조사 방법과 그 방법이 틀렸던 지점

- CI 테이블 36개, API 라우트 38개(메서드 56개), CI 화면·부품 45파일을 전수로 읽었다.
- 화면이 실제로 부르는 것은 `fetch(` 호출과 그 뒤 300자 안의 `method:`를 짝지어 셌다.

⚠️ **처음 쓴 스캐너가 틀렸다.** 경로에 `(ci)` 괄호가 있어 셸이 글로브로 읽는 바람에
`grep`이 **조용히 0건**을 냈다. 그 결과 "삭제 UI는 이슈 하나뿐"이라고 잘못 셌는데,
실제로는 **자료 화면에도 삭제가 있었다**(`AssetsView.tsx:191`).
아래 수치는 전부 python으로 다시 센 값이다. (교훈: 지표부터 검증한다)

| 메서드 | 건수 | 무엇 |

## 3. 원인 셋

### 3-1. 콘텐츠에 변경 경로가 아예 없다 (가장 큼)

`app/api/ci/contents/[id]/route.ts`는 **`GET`뿐**이다. 곁가지 세 개가 전부다:

| 있는 것 | 하는 일 | 한계 |
|---|---|---|
| `POST .../retry` | 수집 다시 시도 | 실패한 것을 **다시** 할 뿐, 없애지 못한다 |
| `POST .../topic` | 주제 바꾸기 | 분류만 |
| `POST .../exclude` | 통계에서 제외 | **화면에 버튼이 없다** |

즉 잘못 들어온 게시물을 사용자가 할 수 있는 일은 "다시 시도"뿐이다.
제목이 틀려도 못 고치고, 남의 링크를 잘못 넣어도 못 지운다.

### 3-2. 서버는 되는데 화면이 안 부른다 (CLAUDE.md §2-5가 경고한 그 패턴)

API 메서드 56개 중 **21개가 화면에서 한 번도 안 불린다.**
대부분은 서버 컴포넌트가 쿼리 함수를 직접 부르기 때문(정상)이지만,
**변경 메서드 5개**는 진짜 기능 공백이다:

| 안 불리는 변경 API | 사라진 기능 |
|---|---|
| `DELETE /api/ci/channels/[id]` | **관심 채널을 지울 수 없다** (소프트 삭제 + 모니터링 해제까지 구현돼 있는데) |
| `POST /api/ci/contents/[id]/exclude` | **통계에서 빼기를 할 수 없다** |
| `POST /api/ci/topics` | **주제를 사람이 만들 수 없다** (AI가 만든 것만 쓴다) |
| `DELETE /api/ci/settings` | 설정을 기본값으로 되돌릴 수 없다 |
| `POST /api/ci/alerts/sweep` | 알림 규칙을 지금 돌려볼 수 없다 |

이건 "기능이 없다"가 아니라 **"만들어 놓고 안 꽂았다"**이다. 화면 배선만 하면 되는 것들이다.

### 3-3. 되돌릴 준비는 돼 있는데 안 쓴다

`deleted_at`(소프트 삭제) 컬럼을 가진 CI 테이블이 **6개**다 —
`ci_assets` · `ci_boards` · `ci_channels` · `ci_contents` · `ci_topics` · `ci_workspaces`.
읽기 경로도 전부 `.is('deleted_at', null)`로 이미 걸러낸다.

**즉 지우는 쪽만 없다.** 되돌릴 수 있는 삭제를 붙이는 데 마이그레이션이 필요 없다는 뜻이다.
(`ci_boards`·`ci_contents`·`ci_topics`는 컬럼만 있고 쓰는 코드가 0이다)

## 4. 사용자가 실제로 겪는 것

| 상황 | 지금 |
|---|---|
| 링크를 잘못 넣었다 | **지울 수 없다.** 수집함에 영원히 남는다 |
| 수집이 실패했다(스크린샷) | 재시도만 된다. 안 되는 링크면 계속 남는다 |
| 관심 채널을 그만 보고 싶다 | 모니터링만 끌 수 있고 **목록에서 지울 수 없다** |
| 보드를 잘못 만들었다 | **못 지운다.** 이름도 못 바꾼다 |
| 보드에 잘못 담았다 | **못 뺀다** |
| 아이디어·기획을 접었다 | **못 지운다.** 단계만 옮길 수 있다 |
| 통계를 흐리는 게시물이 있다 | 서버는 지원하는데 **버튼이 없다** |

수집이 자동이라 **잘못 들어오는 일이 구조적으로 생기는데**, 치울 도구가 없다.

## 5. 기획 — 무엇을 어떤 순서로

**되돌릴 수 있는 삭제(소프트 삭제)를 원칙으로 한다.** 물리 삭제는 쓰지 않는다.
컬럼과 읽기 필터가 이미 있으므로 **마이그레이션 없이** 3-1·3-2를 닫을 수 있다.

### 단계 1 — 이미 있는 것을 꽂는다 (가장 싸다 · 서버 변경 0)

- 채널 목록·상세에 **삭제** — `DELETE /api/ci/channels/[id]` 배선
- 수집함 행에 **통계에서 빼기** — `POST .../exclude` 배선
- 설정에 **기본값으로 되돌리기** — `DELETE /api/ci/settings` 배선

### 단계 2 — 콘텐츠에 삭제와 수정을 낸다 (핵심)

- `DELETE /api/ci/contents/[id]` 신설 — `deleted_at` 소프트 삭제 (컬럼 이미 있음)
- `PATCH /api/ci/contents/[id]` 신설 — 사람이 고칠 수 있는 것만: **제목 · 주제 · 통계 제외**
  (조회수·게시일 같은 **수집값은 못 고치게 한다** — 고치면 지표가 거짓이 된다)
- 수집함·트렌드 행과 상세 시트에 배선

### 단계 3 — 만들 수 있는데 못 지우는 것들을 닫는다

보드(이름 수정·삭제) · 보드 항목(빼기) · 아이디어(삭제) · 기획(삭제) · 편집안(수정·삭제) · 게시물(삭제)
→ 전부 소프트 삭제. `ci_board_items`·`ci_ideas`·`ci_briefs` 등은 `deleted_at`이 없어
**마이그레이션 1개**가 필요하다(컬럼 추가 = expand, 되돌릴 수 있음).

### 단계 4 — 되돌리기와 일괄 처리

- 삭제 직후 **되돌리기**(토스트) — 소프트 삭제라 복구가 UPDATE 한 번이다
- 수집함 다중 선택 → 일괄 삭제/제외 (`ListSurface`가 전체선택을 이미 지원한다)

### 무엇을 안 할지

- **물리 삭제를 만들지 않는다.** 수집 데이터는 지표의 근거라 되돌릴 수 없는 삭제는 위험하다.
- **수집값(조회수·게시일·채널)을 수정 대상으로 열지 않는다.** 고치는 순간 배수가 거짓이 된다.
- 새 UI 부품을 만들지 않는다 — `ListSurface` 액션 칸 · `NbModal` 확인 · `EmptyState`로 충분하다.
