# CRM 미팅 — 지금 무엇이고, 무엇이 없는가 (분석)

- 작성: 2026-08-21 · 기준 버전 v0.7.572 · **분석·기획 전용, 구현 없음**
- 대상 화면: `/crm/meetings`, `/crm/meetings/[id]`
- 사용자 지적(원문)
  1. *"이거 녹음하는것도 없는데 뭘 어떻게 쓰는거야? 음성녹음 버튼이 있어서 녹음하면 … 녹음 끝나고 전사로 변경하고 분석해서 완성하는 그런형태로 되어야지"*
  2. *"미팅 기록과 만들어지고 그걸 클릭하면 전사를 넣어라 이게 하나의 화면으로 합쳐져도 충분한데 왜 모달로 따로 빼고 다시 클릭해서 내용을 넣게 했는지 이상한 UX네"*

---

## 0. 한 줄 결론

**두 지적 모두 맞다. 그리고 코드는 사용자가 본 것보다 더 나쁘다.**

- 녹음은 "아직 안 붙은 것"이 아니라 **설계상 자리만 있고 코드가 0줄**이다. 업로드 라우트도, 잡도, 어댑터도 없다.
- 모달은 "굳이 나눈 것"이 아니라 **나눠 놓고 이어 붙이는 것을 잊은 것**이다. 만든 미팅의 id를 돌려받고도 버린다.
- 게다가 그 옆에 **아무도 모르게 죽어 있는 경로가 6개 더** 있다 — 목록 배지, CSV 내보내기, 단계 점검 AI, 다음 행동 AI가 전부 영원히 빈 값을 받고 있다.

## 1. 지금 화면이 실제로 하는 일 (코드 근거)

### 1-1. 흐름

```
[목록 /crm/meetings]
   └ '미팅 기록' 버튼 → 모달(MeetingFormModal)
        제목 · 날짜 · 시각 · 회사 · 딜 · 장소  → POST /api/crm/meetings
        저장되면 → 모달 닫고 목록 새로고침       ← 여기서 끊긴다
[사용자가 목록에서 방금 만든 것을 눈으로 찾아 클릭]
   └ [상세 /crm/meetings/[id]]
        전사 붙여넣기 → POST …/transcript
        'AI로 정리하기' → POST …/extract → 5축 제안 → 인박스
```

### 1-2. 파일과 크기

| 자리 | 파일 | 줄 |
|---|---|---|
| 목록 | `app/(crm)/crm/meetings/MeetingsClient.tsx` | 127 |
| 생성 모달 | `app/(crm)/crm/meetings/MeetingFormModal.tsx` | 151 |
| 상세 | `app/(crm)/crm/meetings/[id]/MeetingDetail.tsx` | 256 |
| 도메인 | `lib/crm/services/meeting.ts` | 373 |
| 전사 어댑터 | `lib/crm/stt/adapter.ts` | — (`mock` · `pasted` 둘뿐) |
| API | `meetings/route.ts`(GET·POST) · `[id]/route.ts`(GET·DELETE) · `[id]/transcript` · `[id]/extract` | — |

### 1-3. 잘 되어 있는 것 (건드리면 안 되는 부분)

이 기능은 **뼈대가 좋다.** 재설계가 아니라 **비어 있는 칸을 채우는 일**이다.

- `SttAdapter` 인터페이스가 이미 있다 — 업체를 갈아 끼울 수 있게 설계돼 있다(`lib/crm/stt/adapter.ts`)
- 녹음 상태 머신(`UPLOADED → TRANSCRIBING → TRANSCRIBED → SUMMARIZED`)과 재시도 3회 규칙이 이미 있다(`domain/state-machines.ts`)
- `CrmMeetingRecording` · `CrmTranscriptSegment` 테이블이 이미 있다(`fileUrl`은 "Supabase Storage 경로" 주석까지 달려 있다)
- AI가 읽은 것은 **코어에 직접 안 쓰고 제안으로 보낸다**(절대규칙 1) — 이 원칙이 지켜져 있다
- **근거(evidence)를 못 대면 버린다**(`dropUngrounded`) — 그럴듯한 거짓말을 막는 장치가 이미 작동한다
- 미팅을 지우면 미처리 제안도 함께 거둔다(고아 제안 방지, 실측 사고 반영본)

> 즉 **파이프라인의 앞쪽(입력)만 비어 있다.** 뒤쪽(추출·근거·제안·인박스)은 완성돼 있다.

## 2. 지적 ① — "녹음하는 게 없다"

### 2-1. 사실 확인: 없는 게 맞다. 그리고 자리도 안 만들어져 있다.

명세(`newplan/CRM/plan/dacrm_구현명세서_v0.1.0.md` §3.2)는 이렇게 적혀 있다:

> 1. 미팅 생성 후 녹음 파일 업로드: 클라이언트가 **서명 URL 로 Storage 직접 업로드**
> 2. `POST /api/crm/meetings/[id]/recordings { fileUrl }` → `CrmMeetingRecording(UPLOADED)` 생성, 잡 발행
> 3. `jobs/stt`: TRANSCRIBING 전이 → 어댑터 호출 → 세그먼트 저장 → TRANSCRIBED
> 4. TRANSCRIBED 저장 트랜잭션이 `jobs/extract` 발행
> 9. **소요 목표: 60분 녹음 기준 전 과정 10분 이내**

실제로 존재하는 것:

| 명세가 요구한 것 | 실제 |
|---|---|
| `POST …/recordings` | **없음** (`app/api/crm/meetings/[id]/` 아래엔 `transcript`·`extract`뿐) |
| `jobs/stt` | **없음** (`app/api/crm/jobs/`엔 `gmail-sync`·`expire-suggestions`·`stalled-deals`) |
| `jobs/extract` | **없음** (추출은 사람이 버튼을 눌러야만 돈다) |
| Storage 버킷 | **없음** (마이그레이션 전체에서 버킷은 `ai-chat` 하나뿐) |
| STT 어댑터 | `mock`(안내문만 반환) · `pasted`(붙여넣기) — **실제 전사 0개** |
| 녹음 UI | **없음** — 화면 어디에도 마이크 버튼이 없다 |

`sttAdapterFor()`는 `'mock'` 외의 값을 주면 **예외를 던진다**:

```ts
throw new Error(`음성 인식 업체(${vendor})가 아직 연결되지 않았습니다. 지금은 전사를 붙여넣는 방식만 됩니다.`)
```

### 2-2. 화면은 이 사실을 정직하게 말하고 있다 — 그게 문제를 가렸다

상세 화면 안내문:

> 녹음 파일 업로드는 음성 인식 업체를 연결하면 열립니다.

설정 화면도 정직하다 — `stt.vendor`·`stt.api_key`를 **일부러 감춰 뒀다**(`services/setting.ts`의 `PLANNED_SETTINGS`):

> 입력창을 먼저 띄워 두면 사용자는 키를 넣고 아무 일도 안 일어나는 걸 보게 된다 — 그건 빈 칸보다 나쁘다.

**이 판단 자체는 옳다.** 하지만 결과적으로 "업체만 연결하면 열린다"처럼 읽힌다. 실제로는 **업체를 연결해도 안 열린다** — 업로드 라우트·잡·버킷·UI가 통째로 없기 때문이다. 남은 일은 "키 등록"이 아니라 **파이프라인 절반**이다.

### 2-3. 왜 지금까지 안 붙었나 — 진짜 장벽

붙이지 못한 이유가 게으름이 아니라 **세 개의 실제 제약**이다. 기획은 이 셋을 넘어야 한다.

| 제약 | 내용 | 근거 |
|---|---|---|
| **본문 4.5MB** | Vercel 서버리스 요청 본문 한도. 60분 녹음(≈14MB)은 우리 API를 **통과할 수 없다** | `lib/gpu/intake-files.ts:6`에 같은 한도가 이미 기록돼 있다 |
| **실행 300초** | 함수 최대 `maxDuration = 300`. 60분 오디오를 한 번에 전사하면 **거의 확실히 넘는다** | 저장소 최대값이 300 (`analyze-drain`·`leads/parse`) |
| **출력 32,768토큰** | 60분 한국어 회의 전사는 4~6만 토큰. 한 번에 뽑으면 **중간에서 잘린다** | `GEMINI_MAX_OUTPUT_TOKENS = 32_768` (`lib/ai/gemini-call.ts`) |

→ **한 방에 처리하는 설계는 반드시 실패한다.** 쪼개는 것이 선택이 아니라 전제다. (§4에서 이 셋을 동시에 푸는 설계를 제시한다)

## 3. 지적 ② — "왜 모달로 빼고 다시 클릭하게 했나"

### 3-1. 사실 확인: 모달을 나눈 이유가 **코드상 존재하지 않는다**

모달은 재사용을 전제로 만들어졌다. 주석에도 그렇게 쓰여 있다:

```ts
/** 딜 상세에서 열면 그 딜로 고정된다 */
fixedDealId?: string
fixedCompanyId?: string
```

그런데 전수 검색 결과:

```
$ grep -rn "MeetingFormModal" apps/web --include=*.tsx
MeetingsClient.tsx:18   import MeetingFormModal from './MeetingFormModal'
MeetingsClient.tsx:120  <MeetingFormModal … />          ← 호출처 이것 하나뿐
```

- **`fixedDealId` · `fixedCompanyId`를 넘기는 곳이 0곳.** 재사용은 일어난 적이 없다.
- 딜 상세·회사 상세의 '미팅 기록하기'는 모달을 여는 게 아니라 **목록 URL로 보낸다**(`MeetingPanel.tsx:75` → `href: '/crm/meetings'`). 보던 딜을 안 데려가므로 사용자는 회사·딜을 처음부터 다시 고른다.

> 즉 모달은 **한 화면만을 위한 부품**이고, 그 한 화면은 모달을 닫자마자 목록으로 돌아간다. 화면을 나눠서 얻은 것이 없다.

### 3-2. 결정적 증거 — 만든 미팅의 id를 **받아 놓고 버린다**

모달은 저장 성공 시 새 미팅 id를 부모에게 준다:

```ts
// MeetingFormModal.tsx
onSaved: (id: string) => void
…
onSaved(body.id)          // ← id를 정확히 넘긴다
```

받는 쪽:

```ts
// MeetingsClient.tsx:120
<MeetingFormModal
  onClose={() => setCreating(false)}
  onSaved={() => { setCreating(false); void load() }}   // ← id를 안 받는다. 목록만 새로고침
/>
```

**한 줄이면 될 일이다** — `onSaved={(id) => router.push(`/crm/meetings/${id}`)}`. 그 한 줄이 없어서 사용자는 "저장 → 목록에서 눈으로 찾기 → 클릭 → 그제서야 입력"을 한다.

사용자가 *"이상한 UX"*라고 말한 것은 정확히 이 지점이다. 그리고 **이건 설계 의도가 아니라 미완성이다.**

### 3-3. 그러나 "한 줄 고치기"로 끝내면 안 되는 이유

id를 물고 이동시켜도 **여전히 화면이 둘**이다. 그리고 더 근본적인 문제가 남는다:

> **미팅은 "만드는 것"이 목적인 레코드가 아니다.**
>
> 회사·인물·딜은 만드는 순간 목적이 달성된다. 그래서 모달이 맞다.
> 미팅은 **만든 직후가 껍데기**다. 제목과 시각만 있는 미팅은 아무 가치가 없다.
> 진짜 목적은 그 안의 **내용(녹음·전사)**이고, 그건 모달 밖에 있다.

이 저장소에는 이미 **정답 패턴**이 있다:

| 화면 | 방식 | 성격 |
|---|---|---|
| `/crm/deals` `QuickCreateBar` | 화면 상단 캡처 바 — 붙여넣고 누르면 회사·인물·딜이 한 번에 | **캡처** |
| `/lead-intake` | 한 화면 — 붙여넣기 + 파일 + **음성 입력** → AI 파싱 → 확인 카드 | **캡처** |
| GPU 통합입력 | 한 화면 — 파일·붙여넣기 → AI 추출 → 검수 | **캡처** |
| 회사·인물·딜 생성 | 모달 | **레코드 생성** |

미팅은 **캡처**다. 캡처 흐름은 이 저장소에서 한 번도 모달이었던 적이 없다.

## 4. 그 밖에 발견한 것 (지시 밖 발견 — CLAUDE.md M-9 보고 의무)

지시받지 않았지만 조사 중 확인한 것들이다. **총 11건.** 대부분 화면이 아무 이상 없어 보여서 아무도 눈치채지 못하는 종류다.

### 🔴 심각 — 사용자가 겪지만 원인을 알 수 없는 것

**F-1. `summaryMd`를 쓰는 코드가 0곳이다. 읽는 곳은 6곳이다.**

```
읽기: MeetingsClient(배지) · MeetingPanel(딜/회사 상세 배지) · export.ts(CSV '정리됨')
      stage-review.ts(lastMeetingSummary) · next-best-action.ts(미팅 요약) · MeetingDetail
쓰기: 0곳                            ← 전수 검색 결과
```

결과(전부 조용히 죽어 있다):
- 미팅 목록 배지는 **전사를 넣고 AI로 정리해도 영원히 `전사 대기`** — 스크린샷 ②에 실제로 그렇게 떠 있다
- 딜 상세·회사 상세의 미팅 배지도 같다
- CSV 내보내기의 `정리됨` 칸은 **항상 빈칸**
- **단계 점검 AI**(`stage-review`)의 "최근 미팅 정리" 입력은 항상 `null`
- **다음 행동 추천 AI**(`next-best-action`)도 같다 → 미팅을 아무리 쌓아도 이 두 AI는 미팅을 못 본다
- `SUMMARIZED` 상태는 전이 규칙·테스트까지 있는데 **도달할 코드가 없다**
- `meeting_summary` 제안 타입은 라벨(`format/suggestion.ts`)과 테스트 픽스처에만 있고 **생산 코드가 없다**

> 이건 이 저장소가 반복해 온 **"만들어놓고 안 부르는" 사고**의 정확한 재현이다.
> 심지어 `lib/crm/wired.test.ts`가 그 사고를 막으려고 존재하는데, `summaryMd`는 목록에 없어서 통과했다.

**F-2. 미팅을 수정할 방법이 전혀 없다.**
`app/api/crm/meetings/[id]/route.ts`에는 `GET`·`DELETE`만 있다. **`PATCH`가 없다.**
제목에 오타가 나거나 딜을 잘못 고르면 **지우고 다시 만드는 것 말고 방법이 없다.** 지우면 그 미팅에서 나온 미처리 제안도 함께 사라진다.

**F-3. 딜·회사 상세에서 미팅을 만들 수 없다.**
`MeetingPanel`의 '미팅 기록하기'는 `/crm/meetings` 목록으로 보낼 뿐이다. 보던 딜을 안 데려간다.
(2026-08-17 UX 재기획 보고서 §126이 이미 지적한 것 — 아직 안 고쳐졌다)

**F-4. 만든 미팅으로 안 데려간다.** (§3-2)

### 🟡 중간 — 데이터가 조용히 오염되는 것

**F-5. `extract`에 멱등성이 없다.**
`fiveAxisToSuggestions`에 중복 판정이 없다. **'AI로 정리하기'를 두 번 누르면 같은 제안이 두 벌** 인박스에 쌓인다. 실행 중 버튼이 잠기긴 하지만 새로고침 뒤 다시 누르면 그대로 통과한다.
(UX 재기획 보고서가 이미 보고한 24건 중 하나 — 미해결)

**F-6. 목록이 미팅마다 회사·딜 이름을 개별 조회한다(N+1).**
`MeetingsClient.load()`가 미팅 100건이면 최대 200번의 fetch를 병렬로 던진다. 지금은 데이터가 적어 안 보인다.

### 🟢 표준 이탈 — 지금은 안 아프지만 굳으면 비싸다

**F-7. 미팅 목록이 §2-6 목록 표준을 안 쓴다.**
자작 `<ul>`이라 **검색·정렬·필터·페이지네이션이 하나도 없다.** `ListToolbar`/`ListSurface`/`ListPager`+`useListQuery`가 있는데 안 쓴다. 미팅이 200건 넘으면 `limit` 100에 걸려 **오래된 것은 화면에서 사라진다(안내 없이)**.

**F-8. 상세의 오류 배너가 입력칸에서 멀다.**
스크린샷 ①이 그 상태다 — 빈 채로 '전사 넣기'를 누르면 오류가 **페이지 최상단**에 뜬다. 눈은 textarea에 있는데 메시지는 화면 위쪽에 있다.

**F-9. 3열 레이아웃이 이 화면에는 안 맞는다.**
`RecordLayout`은 회사·인물·딜 상세(속성/이력/연결)를 위한 골격이다. 미팅은 **전사가 주인공**인데 가운데 열이 1/3 폭이라 스크린샷 ①처럼 좌우가 거의 비어 있다. 좌열은 `—` 두 개, 우열은 "전사를 먼저 넣어 주세요" 하나뿐이다.

**F-10. 화면 안내가 녹음을 암시한다.**
