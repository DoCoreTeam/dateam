## 목표
- 운영에서 사람이 막힌 결함은 고치는 즉시 밀고, 그 밖은 플랜 완료 때 한 번 미는 것으로 가름
- 그 판정을 사람이 매번 생각하지 않게 플랜 헤더 「푸시」 줄 한 칸에 적고, 훅과 도구가 그 줄을 읽음
- 앞 판 v0.10.994 는 전부 모으게 만들어 오류 수정 반영이 늦어지는 문제가 있었고 이 판이 그것을 고침

## 범위 밖
- vercel.json 의 ignoreCommand 신설
- 크론 주기 조정과 next.config.js 빌드 캐시 재검토
- 끝내지 않고 둔 옛 플랜 파일 넷(P0001·P0030·P0052·P0114) 정리
- 이미 보관된 플랜 파일에 푸시 줄 소급 기재

## 완료 정의
- pnpm tsc --noEmit, pnpm test, pnpm lint, pnpm build 통과
- 푸시 타이밍 판정이 규정(LOOP.md 부록 + 정책 3파일), 저장(플랜 헤더 + 템플릿 두 벌), 읽는 쪽(.githooks/pre-push + loop.mjs), 가드(policy-sync.test.ts) 네 자리에 모두 있음
- 푸시 즉시인 플랜에서 git push 가 실제로 통과하고, 모음인 플랜에서 실제로 거절됨
- 사용자 노출 문자열 없음, i18n 해당 없음
- 설정값 추가 없음, env 해당 없음

### I03 훅과 도구가 그 줄을 읽어 움직인다
상태: 대기
모드: 경량
범위: .githooks/pre-push, scripts/loop.mjs
감사 기준:
- 푸시 즉시인 플랜이 활성일 때 git push --dry-run 이 종료코드 0 으로 통과
- 푸시 모음인 플랜이 활성일 때 종료코드 1 로 거절되고 거절 메시지가 즉시로 바꾸는 법을 함께 알려 줌
- 푸시 줄이 아예 없는 옛 플랜 파일은 모음으로 보고 막음(안전한 쪽), 그 사실이 메시지에 적힘
- loop pass 출력이 즉시면 지금 밀라고, 모음이면 모으는 중이라고 서로 다른 말을 함
- 일부러 깨 보기: 즉시 판정을 반대로 바꾼 판으로 두 경우를 실행해 결과가 뒤집히는 것을 확인하고 되돌림
