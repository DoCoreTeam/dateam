## 목표
- 메뉴 「AI 트레이딩」이 소유자에게만 열리고, 그 안에서 KOSPI200 선물 1분·5분 확정 봉이 빠짐없이 쌓임
- 봉이 확정될 때마다 진입 조건을 보고 `rule`과 `jev` 판단을 **알림 없이** 기록함, 봉 하나에 판단 하나
- 나중 단계(1-B 검증, 1-C 알림)가 쓸 시각·버전·유일 키가 이때부터 다 남음

## 범위 밖
- 주문 API 호출 (M1, Release 4 전까지 코드에 없음)
- 백테스트·체결 재현·보정·기대값·관문 (1-B)
- 계좌 조회(잔고·체결·미체결·증거금)·알림 발송·신호 화면 단추·체결 연결·손익 (1-C)
- Gemini 지식 카드·AI 운영자·야간장 신호 (Release 2·3)
- 위 것들의 빈 함수와 임시 코드도 만들지 않음 (명세 「구현 범위 잠금」)

## 완료 정의
- pnpm tsc --noEmit, pnpm test, pnpm build 통과
- 사용자 노출 문자열은 `@/lib/terms` 용어집 상수를 씀 (이 저장소에 i18n 라이브러리가 없음, 부록 「말」 참조)

- 저장소에 KIS 주문 API 를 부르는 코드가 없고 그 사실을 가드가 셈
- `docs/trading/ASSUMPTIONS.md` 에 기존 코드로 못 찾아 기본 구현으로 간 자리가 전부 한 줄씩 적힘

- 크론 실행 자체가 `(job_name, scheduled_minute)` 로 한 번만 돎
- 50초가 넘으면 남은 일을 다음 실행으로 넘김 (테스트가 시계를 밀어 확인)

### 1-A 의 「끝났다는 기준」은 아직 못 채움 — 운영에서만 확인할 수 있음

명세 §3.2 가 1-A 의 완료 기준으로 「5거래일 결측 없는 수집」과 「판단 기록이 봉마다 한 번만」을 든다.
이 둘은 **배포 + KIS 실계정 + 5거래일**이 있어야 답이 나오고, 코드로는 답할 수 없다. 지금 상태는 그 측정을 시작할 수 있는 상태다.

배포 전에 사람이 해야 하는 것 다섯 (`docs/trading/ASSUMPTIONS.md` 에도 있음)

1. `trading_settings` 의 `owner_user_id` 지정 — 비어 있으면 **아무도** 화면에 못 들어감(일부러 그렇게 함)
2. KIS 조회 전용 앱키·시크릿 등록 (`saveTradingCredentials`)
3. `jev_model` 지정 — 비우면 `rule` 판단만 기록되고 Jev 는 안 불림
4. pg_cron 활성화: `ALTER DATABASE postgres SET app.trading_tick_url / app.trading_tick_secret` 후 마이그 280 재실행
5. 세션 캘린더 채우기(`seedRegularSessions`) + 휴장일 정리

배포 뒤 첫날에 확인할 것 둘 (둘 다 코드가 아니라 **실데이터**로만 답이 나옴)

- 분봉의 `stck_cntg_hour` 가 봉 시작인가 끝인가 — 끝이면 저장이 1분씩 밀린다
- 조회 API 가 마스터의 `A01612` 형식 코드를 받나 — 안 받으면 오류가 아니라 빈 응답이 온다

### 부수 발견 (트레이딩과 무관, 안 고침)

`apps/web` 아래 `.next-*` 잔여 빌드 디렉터리가 20개 넘고 그중 셋이 2.7~3.1GB, `tsconfig.json` 의 `include` 에도 남아 있다.
기본 힙으로는 `tsc` 와 `build` 가 OOM 으로 죽는다. 다른 세션이 남긴 것이라 지우지 않고 보고만 한다.
