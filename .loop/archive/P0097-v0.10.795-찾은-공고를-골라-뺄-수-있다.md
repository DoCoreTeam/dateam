## 목표
- 상관없는 공고를 **한 건씩 또는 골라서 한 번에** 목록에서 뺄 수 있음
- 뺀 것을 **다시 보고 되돌릴 수 있음** — 빼기는 되돌릴 수 있어야 누를 수 있다
- 케이스로 만든 공고가 **목록에서 실제로 빠짐** (지금은 안 빠진다)
- RFP 화면도 저장소의 삭제 계약 가드가 보게 되어 같은 구멍이 다시 안 생김
- 목록 줄의 **단추가 한 세로줄에 선다** — 지금은 제목 길이를 따라 좌우로 흩어진다

## 범위 밖
- 공고 원문(rfp_sources) 자체를 지우는 일 — 적중만 뺀다. 원천을 지우면 다음 훑기에 또 들어온다
- 규칙 자체를 고치는 일 (이미 있음)
- 케이스 삭제 창구 신설 (P0094 에서 없다고 기록한 것, 별건)
- 자동으로 빼 주는 판단 (무엇이 상관없는지는 사람이 정한다)

### 3 실브라우저 실측 (격리 서버 :3210, NEXT_DIST_DIR 분리, 로그인 상태)

단추 배치 — 공고 레이더 57줄
```
고치기 전  1280 폭: 단추 오른쪽 끝이 44가지 자리 (831·1220·230·256·115·167…)
고친 뒤    1280 폭: 1272 한 가지          390 폭: 382 한 가지
두 폭 다 가로 넘침 0
```

빼기와 되돌리기 — 전체 흐름
```
찾은 공고 50줄 → 한 줄 빼기 → 49줄 (PATCH 200)
셋 고르기 → 「고른 공고 3」 배지 → 한 번에 빼기 → 47줄 (PATCH 200 한 번)
「뺀 공고 보기」 → 제목이 「뺀 공고」로, 되돌리기 1건, 케이스로 만들기 0개
되돌리기 → 뺀 공고 0줄 → 「찾은 공고로 돌아가기」 → 50줄 복귀
```
시험이 바꾼 운영 데이터는 매번 되돌렸고 마지막 상태는 `new=80`, `dismissed=0` 이다.

공유 :3000 dev 서버가 JS 청크를 404·text-plain 으로 주고 있어 하이드레이션이 안 됐다 —
단추는 그려지는데 클릭이 아무 일도 안 한다. 내 코드 문제로 오진할 뻔했고 격리 서버로 옮겨 확인했다.
